# 错误恢复与结果判读

## 传输区别

- CLI：普通成功为stdout业务JSON和退出码0；失败为非零退出与受控错误。不能用“有JSON”判断成功。login先输出authorization_pending事件，最终员工结果才表示完成；不要将其stdout整体按单一JSON解析。
- SDK：已通过统一解码器验证并解包data，失败抛ServiceError；按status/code/recovery/outcome_unknown及trace_id判断，不解析异常字符串中的数字作唯一依据。
- MCP：isError为真即工具失败，正文包含统一业务错误；HTTP传输200或有content不证明业务成功。
- 飞书、ArkCLI的ok、exit10、--yes、--dry-run等不是企业办公协议，禁止直接套用。

## 故障分流

| 情况 | 处理 |
|---|---|
| CLI不存在／SDK不在脚本环境 | 说明缺少依赖，走可信安装流程；不下载未知链接 |
| 钥匙串不可用／记录损坏 | 让员工修复本机安全后端或重新授权；不读原始存储、不明文回退 |
| 401／本地missing、expired | 认证参考；恢复后继续原任务，不擅自切服务或账号 |
| 403 | 当前员工未开通或无权限；解释拒绝并交管理员处理，不循环登录 |
| 409 | 重新读取当前对象／版本与字段，再预览和确认；不复用旧摘要覆盖 |
| 422字段或参数问题 | 依据当前契约修正，不伪造新字段、假ID或未支持flags |
| 422015导出预算超限 | 结果没有返回部分数据；不能当拼写错误或降低max_records来取完整报表。联系管理员规划分段或缩小真实业务范围；当前接口没有分段功能 |
| 429／身份服务5xx | 当前刷新暂不可用，SDK保留凭证；稍后按当前身份恢复，不借新账号重试 |
| 业务5xx、超时／网络／不可信响应 | 写入结果可能未知；先查询原对象／操作、说明关联号，不自动重放写入 |
| 账号pending/running | 仅表示处理进行中；每批最多10次只读状态查询，未完成就报告状态及操作ID，不重新开户 |
| cleanup=failed/pending | 业务访问已停，身份清理仍需核对；获准后才重试清理，不说已全部注销 |

读取失败不是空数据，权限不可见不是不存在，缺数不是零；分页未完不是全集。日志和对话只保留必要ID、业务码与关联号，不输出密码、令牌、原始HTTP异常或敏感资料。

## 对员工的回复

说清：做了什么、哪个服务／对象、实际阶段、结果或阻断原因、下一步。示例：

- “已保存为待核对记录，尚未业务确认。记录编号…。”
- “报表图文已生成并通过校验，尚未发送。目标群…，请核对。”
- “停用已生效；身份登录清理尚未确认，关联号…。”

不要只返回一串ID，也不把原始大JSON、凭证元信息或内部调试日志当业务说明。
