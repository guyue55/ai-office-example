# 工作台视觉修整：方案与验收

日期：2026-10-26；分支codex/agent；起点faae523。依据联网视觉审查及独立Chrome颜色测量；范围为共享样式、助手占位和人员授权说明，不变更服务端操作、权限、审批和数据库。

## 任务与取舍

1. 初始加载占位纳入统一生命周期；刷新／切页恢复已有会话后不得残留“正在准备助手”，空态／失败态也不能与加载态混在一起。
2. 辅助文字、控件边界、焦点环采用独立共享变量；辅助文字在白卡及灰底达到普通文字4.5:1目标；必要控件边界和焦点与实际相邻背景达到3:1目标。卡片装饰线不机械加深，禁用控件另行判断。
3. 焦点颜色不依赖企业品牌色；深色导航采用浅色焦点，白底账号弹层恢复深色焦点。保持同一套键盘语义，不复制组件。
4. 人员页缩短重复说明；待认领区域默认收起，数量和展开入口保持可见。授权流程帮助使用原生details，角色／权限共享变更的风险提示继续直接显示。
5. 窄屏消息正文与输入提高至16px；PC保留原密度，次要标识不当作正文。没有新的GSAP／字体／前端框架依赖，保持减弱动态效果规则。

## 依据及边界

[WCAG文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[焦点可见](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。颜色目标为本轮选定组合，不声称全部页面、任意品牌色及状态均已认证。技能中营销官网、外部字体和深色主题建议不适用，不照搬；简单过渡继续CSS，未引入GSAP。

测试只用隔离身份和合成数据，不读取真实账号；空列表截图不足以证明真实列表体验，需构造长列表补测。真实缩放、读屏、Windows、实体触屏和实际业务可用性研究仍独立验收；不部署、推送或发布。

## 悬浮入口纠偏（2026-10-26）

用户指出原约定的“右下角悬浮按钮→右侧助手”没有实现到位。源码核对确认：入口原来位于 main 首行，低于1200px点击还会强制跳转完整工作区；工作区本身不显示第二套入口。前次仅核验工作区和页面可用性，没有覆盖入口的产品约定，这是验收遗漏。

参考 [CopilotKit Sidebar](https://docs.copilotkit.ai/reference/components/CopilotSidebar) 的固定侧栏与浮动触发器、[assistant-ui Modal](https://www.assistant-ui.com/elements/assistant-modal) 的角落入口与可收起会话结构，以及本地 BeefTV 的 `web/src/pages/canvas/canvas-assistant-sidebar.tsx` 中可复用抽屉、历史、新会话与独立控制器分工。只吸收交互结构，不复制其业务逻辑或引入 React／云服务。UI技能生成的营销首页、外部字体及暗色建议不适用于当前业务控制台；采用既有设计变量和SVG图标，简单悬浮状态使用CSS，不引入GSAP依赖。

已调整：有agent.run权限的业务页面在视口右下角显示固定按钮；开启同一助手面板后隐藏入口，通过面板收起按钮或原有Esc操作关闭。移除窄屏强制跳转；大屏并排，小屏覆盖，保留关闭按钮与完整工作区。面板复用原会话、审批、权限与传输，不新增第二套Agent或状态存储。完整工作区仍作为专用长对话页面，不重复叠加另一套聊天面板。
