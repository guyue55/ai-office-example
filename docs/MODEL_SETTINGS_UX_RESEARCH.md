# 智能助手配置交互调研与改版建议

日期：2026-10-28。项目源码基线：8e1cda5，分支 codex/agent。
状态：本次调研之后已实施，见[主流程实施计划](plans/2026-10-28-model-settings-workflow.md)。本文保留调研时点的分析与建议；实际实现及验证以实施计划和运维说明为准。调研本身未修改应用、实例配置或凭证，未调用真实供应商。

## 1. 结论

当前页面实现了可靠的配置管理，但将内部状态管理暴露成了业务人员的操作流程。推荐改为“填写连接 → 获取或输入模型 → 就近测试 → 保存并启用”，获取列表、测试均可基于当前未保存输入执行，不强制先保存。配置修订、审计、并发检查继续在后台完成。

不是所有成熟产品都采用同一种保存机制，也不是所有“连接检查”都执行模型调用。借鉴就近操作、可搜索模型、手动输入和渐进展开，不直接复刻整套框架。

## 3. 当前页面的具体问题

1. 模型ID纯手填，早于URL和密钥出现；没有基于当前连接获取列表的能力。
2. URL、协议鉴权、凭证模式、自定义密钥头、保留／替换／清除操作分散，普通默认配置也要读完专业设置。
3. 测试基于已保存修订；编辑后旧修订操作被禁用，用户必须保存，且可能需要滚动寻找按钮。
4. “保存草稿”“保存并测试”“测试草稿连接”“启用修订”并列，用户需要理解内部修订才能完成接入。
5. 测试回执位于另一栏，当前输入、已保存草稿和实际运行配置容易混淆。
6. 这些问题不能只靠移动按钮解决：ModelDraft强制model，模型目录无相应接口，ModelConnectionTest.revision有非空外键，前端不能直接传未保存连接完成全部流程。

## 4. 推荐首屏与信息结构

PC优先，使用既有Jinja、原生JS、共享表单／图标／提示／浮层与设计变量，不为此单页引入React、组件大框架或新网关。

```text
智能助手配置                            当前：已启用 · 模型ID
填写连接，选择模型后测试并保存。

API协议        [OpenAI Chat / Responses / Anthropic       ▾]
服务地址       [https://api.example.com/v1                 ]
API密钥        [已配置密钥／输入新密钥                  👁]
               已配置时：[更换] [清除]；默认不要求选择密钥操作

使用模型       [搜索已有模型或输入模型ID           ▾] [↻] [测试连接]
               ↻：获取／刷新模型列表；按钮有tooltip和可访问名称
               未找到？使用“xxx”作为自定义模型ID
               ✓ 当前输入的模型调用通过 · 420ms

▸ 高级设置：鉴权方式、网关参数、超时与预算
▸ 配置详情：当前生效／已保存信息、最近测试与历史

[保存] [保存并启用]                        [停用助手（已启用时）]
```

布局建议而非像素定稿：主表单约760—880px最大宽度；字段采用统一标签与控件对齐；首屏优先完成连接主任务。状态摘要紧凑显示，不再使用大侧栏重复整份草稿。常用动作按钮就近有文字，刷新／显隐密钥等次要操作用SVG图标与tooltip；不能把所有操作都隐藏成难猜图标。

保存与启用要合并为一次用户动作，但后台仍先持久化、再应用；只保存保留给暂不切换者。应用失败时明确“已保存，尚未启用”，保留原运行配置，不误报全部失败，也不重发模型请求。

高级内容遵循渐进展开；协议选Anthropic时再显示相关鉴权选项，自定义头名称仅相应模式显示，无密钥模式隐藏密钥区。默认不展示请求次数、所有预算、配置修订号和运维原理。沿用现有低饱和配色、字体与焦点样式，不采用技能检索建议的营销漏斗／高饱和分块风格，也不加载外部字体。

## 5. 模型选择与刷新

- 使用支持键盘的可编辑combobox，精确ID为实际值，展示名只是辅助。可搜索、直接输入、自定义使用，单个助手仍只选一个默认模型。
- 刷新按当前URL、协议、鉴权和参数取目录；无需选择模型，无需保存。刷新失败保留已输入模型和已有候选，不清空用户内容。
- OpenAI Chat与Responses可复用OpenAI模型目录接口，但目录可见不证明两种推理协议均可用。Anthropic使用对应SDK模型接口及分页，不把OpenAI目录规则硬套过去。
- 目录404／不支持显示“此服务未提供模型列表，可直接填写模型ID”；401显示凭证问题，429显示限流，超时显示网络提示，禁止统称“连接失败”。
- 列表为空仍可输入；当前已选模型不在目录时保留并标注“手动输入／当前列表未返回”，不自动替换。
- 默认不按名称猜模型能力并隐藏不认识的模型。只在上游可靠元数据明确时辅助标注文本／嵌入等类型；未知不是不可用。测试针对所选协议与模型进行。
- 列表与查询在页面内存缓存，绑定当前连接身份；URL、协议、密钥动作、鉴权、header/query改变后失效。不把模型密钥存入localStorage、sessionStorage、HTML回填或前端日志。
- 为大型网关提供本地搜索、窗口化或分批加载；服务端要有页数、项目数、字节和总时限上限，返回是否截断。不能无限自动翻页，也不能把截断目录叫“全部模型”。具体上限在实现阶段用夹具验证，不作为对供应商的统一条数限制。
- 不自动周期刷新、不每按一个字请求目录、不遍历所有协议、不在失败时改地址或密钥碰运气。

## 6. 测试按钮与反馈

推荐在“使用模型”行右侧放常驻文字按钮“测试连接”，刷新在旁；若在密钥行再提供快捷入口，调用同一个测试操作，不形成第二套检测。已有选定模型时随时可测当前输入，没有模型则就地提示先选或输入，不偷偷选择高价模型。

区分两类结果：

| 动作 | 需要模型ID | 发出请求 | 能证明什么 |
| --- | --- | --- | --- |
| 获取／刷新模型 | 否 | 目录请求，不自动推理 | 目录可访问，返回候选ID |
| 测试连接 | 是 | 固定短合成输入的一次所选协议调用 | 此刻所选模型基础调用可用 |

目录请求不宣称“绝对免费”，但本项目不触发推理；实际供应商计费规则由其决定。推理测试保留明确费用告知和既有人工确认，可用同一风格就近确认弹层；不强制先保存、滚动、确认保存再确认测试。重复点击不并发发送，超时／断开不自动重试收费调用。

结果在按钮下方固定区域显示：未测试、测试中、通过、失败、结果待确认。错误摘要为中文、可操作，技术详情折叠，含追踪号，不直接展示供应商原始正文、秘密或整页异常。

输入变更即显示“参数已变更，需重新测试”；请求期间变更或关闭页面，旧回执不得把新配置标绿。客户端取消不能宣称上游没有收到请求或不会计费；复用现有有界收尾、已知结果留存与未知结果表达。

## 7. 服务端适配与安全边界

所有发现／测试经受控服务端执行，复用三协议适配、密钥加密引用、出口DNS固定、响应字节预算、权限和CSRF，不从浏览器直连供应商。

建议两类人工专用操作：当前连接的目录发现、当前配置的临时探针。它们均接收当前输入，而不是要求先有修订号；保存／启用保持独立原操作。具体路由、DTO及迁移需在开发设计时定稿，不在本调研中宣称已新增。

重点：

1. 目录输入只含连接相关字段，不需要任务预算或模型ID。探针输入另带所选模型与费用确认，不要求填无关业务字段。
2. 新密钥仅本次请求临时使用；已存密钥由服务端按修订读取，不发回浏览器。更换URL时不自动把原密钥发往新主机，需明确选择继续使用已有密钥或填写新密钥；提示一次且就近，避免隐性外发或繁琐兑换。
3. 页面上“已配置密钥”只是占位状态，不能把一串星号作为真实密钥提交；清除、更换、保留要有明确后端语义。
4. 沿用读／管理／测试权限；当前未保存输入探测建议需管理与测试权限，测试已存配置沿用原测试权限。无需为每个图标新建一个权限。后端再次核验，不能只依赖按钮显隐。
5. 测试仍留审计、结果和取消收尾，但不因此生成正式配置修订。当前测试表非空revision与最新结果查询必须改造，不能伪造修订号或自动保存来绕过。推荐扩展现有测试记录以表达“已存修订／临时配置”，用来源约束维持一致性；兼容旧查询、输出及恢复逻辑，禁止平行再造一套测试执行器。
6. 测试结果绑定当前配置与凭证版本的服务端不透明标识；不得把原始密钥或可离线猜测的密钥哈希暴露给浏览器。暂存结果不能在后续任意配置保存时被当成验证通过；保存时重新比对内容与版本，不自动再次调用模型。
7. “保存并启用”复用原应用层并发、权限和活动任务限制，不自动停止他人任务、不绕过数据使用许可。许可确认可放在保存并启用时的同一次确认，不在目录发现阶段要求业务数据许可。
8. 模型目录属于不可信外部数据：校验ID／展示名长度与结构，纯文本展示，去重但不改ID前缀、大小写或路由别名。目录中的URL、HTML、定价或能力声明不可直接执行或当成可信事实。

## 8. 实施顺序与验收建议

本轮仅记录建议；后续开发按完整链路实施，不能先接按钮却没有后端能力。

1. 抽取连接输入与统一临时探针目标；设计测试记录迁移、审计与旧接口兼容。
2. 补三个协议的目录读取与临时测试；覆盖当前输入、新／已有／无密钥、自定义头、query、出口限制及取消。
3. 精简表单，复用combobox／输入组／按钮／状态反馈；无JS保留可用的手填与明确提交回退，不宣称无JS也有自动目录。
4. 接保存并启用、失效回执与局部提示；更新契约、操作文档及既有浏览器验收。
5. 隔离PG＋合成协议服务器＋真实浏览器验证；普通与Agent镜像分开检查。真实供应商验证仍需明确调用授权，不能由UI测试代替。

必测：无需保存即可获取列表／测试；目录失败可手填；刷新保留手工模型；大目录截断可见；键盘选择与Esc焦点；模态／抽屉和PC并排布局；输入改变时旧回执失效；连续点击只发一次；取消不误报未调用；无密钥不读取宿主凭证；保留密钥在服务端解析；更换主机不静默外发原密钥；测试不改变活动配置／正式修订；保存并启用部分失败说明准确；普通用户直接调用也被拒绝；无JS回退。
