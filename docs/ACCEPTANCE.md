# 验证方法与使用边界

本模板的验证以当前提交对应的 [GitHub CI](https://github.com/guyue55/ai-office-example/actions/workflows/ci.yml) 为准；不引用其他仓库、旧历史或已失效运行记录作为当前证据。测试命令见 CONTRIBUTING.md。

## 自动验证范围

- Gitleaks 完整可达历史扫描。
- Python 3.13／3.14 的格式、类型、架构、技能、契约、非 live 回归与构建。
- Windows 客户端双版本、完整员工交付包安装及重复执行。
- Linux 服务容器、临时 PostgreSQL、聚合与撤权、数据库迁移及就绪边界。

工作流文件只是配置，任务实际结果以对应提交的 Actions 页面为准。CI 产物是候选制品，不等于 GitHub Release、专业渗透测试或生产上线。

## 交付验证

候选须核对来源提交、包名、轮包内容、源码归档排除规则及 SHA-256；许可证与 NOTICE 应覆盖源码、三个 Python 发行包、技能包、员工交付包和服务容器。独立安装检查不读取已有凭证，也不升级宿主全局工具。

修改公开产品配置时，要验证非默认命令与身份命名空间，不以默认示例通过代替企业副本验收。

## 目标环境仍需验收

- AI 宿主技能发现、自然语言操作及模型对规则的遵守。
- 员工本人浏览器登录、系统钥匙串交互与独立物理电脑环境。
- SMTP、企微等获准连接器的投递及回执。
- 企业数据口径、外部数据库现场接入、容量与 HTTPS 信任。
- 企业二次开发、升级迁移及实际制品的第三方许可合规。

当前不提供图形 Logo／favicon 配置、内置模型、行业业务成品或任意 SQL。未发布版本不构成生产支持承诺，测试通过不能消除目标环境验收。
