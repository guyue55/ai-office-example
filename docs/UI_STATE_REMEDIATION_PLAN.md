# UI状态流转整改计划

日期：2026-10-27。范围：全UI代码审阅发现的五项问题；不改业务模型、权限、CSRF、版本与幂等协议。

## 设计与顺序

1. 页面刷新：抽屉内容解析与完整页面刷新区分；保留原助手入口及当前位置节点，防止事件绑定丢失。不引入新的布局容器，避免破坏工作区高度和无JS布局。
2. 草稿保护：异步写入之前核对其他表单，取消放弃则不发请求；等待请求时新产生的其他草稿不得被自动刷新覆盖。刷新不能安全执行时明确提示操作已提交、列表待刷新，不自动重试写入。
3. 助手生命周期：beforeunload仅提示草稿；pagehide负责清理，取消离开后轮询继续。保留关闭、隐藏页面、最大轮询次数及失败预算规则。
4. 控件状态：保存期间只临时禁用原可用提交按钮，finally恢复其原状态，保留组件原本禁用的按钮；覆盖成功、冲突和未知网络结果。
5. 文档：修正Web模块职责及失效参考，明确浏览器BFF、服务端Agent与客户端Agent的边界。

## 验收与门禁

- 先新增隔离浏览器行为回归，在原实现上确认失败，再实施修复。
- 保存后助手入口及位置节点仍是原节点，助手可再次打开／收起。
- 待认领草稿与其他行操作共存：拒绝放弃不执行；确认放弃再执行；网络等待期间输入的新草稿保留。
- 运行中合成任务：触发真实浏览器离开提示并取消，状态读取继续，不调用模型。
- 原禁用按钮在成功／409／网络错误后保持禁用，提交按钮恢复且请求不重复。
- 相关Web测试、22页面×5宽度及助手／账号／校验浏览器回归；共享代码扩大离线回归与静态门禁。真实账号、密码及授权不修改，不发生模型计费。

## 执行状态

五项均已实施。抽屉解析按用途裁剪，完整列表更新保留原助手入口与位置节点；异步提交按表单版本捕获获准放弃的草稿，请求期间的新草稿阻止自动刷新；当前提交表单等待期间inert，收到成功回执后更新草稿基线，失败时保留输入并恢复原控件状态。完整页面授权保存也覆盖，避免把已经保存的当前表单误判成其他草稿。
