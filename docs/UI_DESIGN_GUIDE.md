# 工作台 UI 设计与复核经验

本文件保存可复用规则；本轮实现、失败记录与验收事实见[重构账本](WORKSPACE_UI_REFACTOR.md)，历史阶段见[整体升级计划](UI_UPGRADE_PLAN.md)。规则来自项目中已复现的问题及设计资料，不等同于全部页面已通过真人验收。

## 从任务决定页面，而非从组件决定页面

- 概览用于快速判断和进入任务；完整权限、角色等低频详情按需展示。不能因为资料已经取得，就全部铺在首页。
- 有详情的统计卡使用一个整卡原生链接，标题与数字共享入口；保留键盘焦点、可访问名称和无JS回退。不要再叠一个重复的“查看↓”链接。
- 数据来自完整授权集合才可画整体分布；当前页数据只能标为当前页。无时间序列不画趋势，不以配置数量推断实际有效权限、使用频率或在线状态。
- 列表优先展示完成判断所需的字段。摘要有数量上限、总数和截断说明；长文可聚焦查看，重要风险与未知结果不能只放在悬浮提示里。
- 每页记录主要任务、首屏常驻信息、按需详情、主动作和失败恢复；共享样式通过不能替代逐页任务审查。

## 弹窗、抽屉与完整页

- 短编辑和核对复用共享Dialog；上下文资料复用共享面板；复杂、多阶段或密集资料保留完整页。
- 仪表盘详情弹窗内的角色配置进入完整页，避免再叠抽屉。不要复制一套弹窗或授权规则来解决组合冲突。
- 复用现有节点及关闭机制，验证重复开关、Esc、焦点返回、背景隔离和真实下一步跳转。无JS仍有可读内容。
- 表格行操作增强可能把文字转为图标；移动到弹窗后，重绘和样式也可能隐藏它。必须在最终容器中验证可见与可点击，必要时显式保留文字。
- 提示气泡应保持可悬停、可聚焦和Esc退出，同时不得遮挡下一行按钮。顶部空间不足时先考虑侧面定位；不能用强制点击掩盖遮挡。

## 共享状态与内容边界

- 完整助手页的可见性与侧栏打开偏好是不同状态；完整页只更新会话选择，不能擅自把侧栏设为展开，也不能覆盖其宽度。
- 共享布局尺寸服从同一变量；助手专属间距覆盖曾造成位置栏上移。以浏览器坐标及断点复核，不只看CSS文本。
- 空待办队列不应挤占首屏；无数据、无匹配、无权限和配置失败分别解释，并提供适当下一步。
- 服务端错误页应提供共享面板可识别的有界错误原因。不能整页提取main，也不能只显示笼统HTTP状态而丢失已知原因。
- 写入指引与控件一样按实际权限呈现。阶段组件只表明当前阶段，不能将“处理回执”或安全页回跳表示为成功。
- 敏感字段使用稳定标记，显隐后仍应排除草稿快照；不记录密码、令牌或用户资料。

## 实例故障不能误判为页面缺陷

- 新身份库与旧配置不匹配时，分别检查登录兑换、在线校验、账号管理连接；它们是不同客户端。
- HTTP健康、身份发现成功不证明登录或账号搜索成功；用真实受控的只读调用核实，真人登录由本人完成。
- 不通过放松认证、覆盖旧秘密、占用其他项目端口或反复重放回调解决故障。既有实例、业务数据与秘密继续保留。

## 二次复核和文档维护

1. 用具体触发和修复前证据确认问题，区分事实、设计判断与未知。
2. 实施最小内聚修复，检查共享组件的其他消费者，特别是浮层与表单组合。
3. 用不同于首轮的证据复核：例如源码定位后做坐标量测，截图后做真实点击，显示成功后检查回执；保留失败与跳过。
4. 新增页面/组件同步tests/ui-pages.json及页面目录上下文；测试数量来自本轮实际输出，不累计重复执行。
5. 每批实现或关键结论变化时同步文档：长期规则进入AGENTS入口与本指南，执行步骤进入操作手册，逐次事实进入账本。旧结论失效时标明被什么替代，不保留相互冲突的“完成”声明。
6. 文档与实现一起按任务边界提交。提交不能暗示推送、发布或部署；纯文档只核查链接、实现描述和差异，不重跑全部活体测试。

## 设计资料

- [PatternFly卡片](https://www.patternfly.org/components/card/)：摘要与详情入口。
- [Atlassian面板](https://atlassian.design/components/panel/usage)：按内容复杂度选择承载方式。
- [Carbon对话框](https://www.carbondesignsystem.com/building-blocks/core/patterns/dialogs)：控制中断与交互复杂度。
- [Carbon空态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)：按原因给出上下文和恢复。
- [Atlassian间距](https://atlassian.design/foundations/spacing)：共享尺度与页面层级。

后续资料需核对当前版本与适用条件；设计体系提供参考，实际取舍仍以本项目任务和实测结果为准。

## 选择与筛选的新增经验

- 分页授权编辑的全选必须明确仅作用本页；其他页保留项单列，部分选中用原生indeterminate状态表达。撤销只恢复当前表单原值，不调用保存。
- 已应用筛选与未提交筛选输入分开；按各页真实支持字段展示，可逐项移除并重置页码，保留作用范围和其他条件。URL构造使用框架真实API并测试参数保留，不能只核对模板可编译。
- 候选账号先比较身份信息，再展开目标的编辑区；不能按同名自动选择，也不能把展开视为确认关联。

## 页面语义与视觉重构

- 页面主标题用h1，分区用h2；不能用标题级别代替字号。完整助手主标题与嵌入侧栏标题分别定义，标题提取/焦点恢复与活体脚本一起迁移。
- 更换导航表面时同步核对文字、活动态、账号菜单和焦点；只改背景容易形成不可见控件。
- 表单按逻辑任务分fieldset，避免把所有输入铺成同一层级；原生提交字段和确认机制保持。
- 处理中回执、需本人操作、需核实与成功分别表达；自动刷新必须复用草稿及待回执保护，不直接刷新绕过确认。

## 展开组件的适用边界

- 先按“帮助、业务操作、任务队列、元信息、可选长内容”分类。不能用details统一收纳低频内容，让页面变成标题猜谜。
- 通用帮助有明确命名的入口，短帮助复用只读弹窗；业务操作放在对应操作区，短表单复用表单弹窗。操作名称说明结果，不能仅叫“高级”。
- 一两行配置标识/版本直接显示，不为短元信息多加展开动作；安全影响、当前失败与必要操作不能只藏在说明里。
- 高级筛选保留按需展开，但已应用条件在外部可见、可移除；技术JSON保留可选展开，核心结果常驻。
- 不按源码details数量机械替换：账号菜单、原生无JS回退与页面可见accordion是不同用途。重要待办须至少常驻明确数量和任务入口，不能当作不重要说明藏掉。
- 每次变更验证入口、实际打开内容、关闭回焦、无JS和取消零写入；不要为了减少展开而造成弹窗/抽屉叠层。
