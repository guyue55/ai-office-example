# 企业 Agent 聊天体验：完整链路调研与实施取舍

日期：2026-10-26；状态：调研已用于界面实施，完成项与证据见[实施账本](AGENT_CHAT_VISUAL_IMPLEMENTATION.md)。范围：ai-office-example 的 codex/agent 分支；调研时界面代码基线 `2e19f71`。本文补充并校正[视觉方案](AGENT_CHAT_VISUAL_DESIGN.md)，不将研究结论等同于员工实测或上线验收。

## 1. 研究结论

推荐继续使用“业务工作台＋并排助手＋独立工作区”，重点重组前端呈现，不更换后端／模型运行时，也不为改聊天外观引入React全家桶。

界面应呈现三类不同信息：AI提出的说明、等待人决定的提案、后端实际执行的回执。它们不能用同一套绿色完成气泡混在一起。普通阅读保持简洁；有业务后果的操作必须容易看见、理解和核对。

信息精简的顺序是：删除重复内容→按场景显示→低频动作移入菜单→熟悉的低风险操作图标化。不能反过来把所有文字按钮替换成图标，再补Tooltip让员工猜。

本轮覆盖布局、导航、空态、输入、上下文、消息排版、工具回执、审批、状态、失败恢复、无障碍、性能和复用。选型与功能边界均围绕当前已实现能力，而非把参考库提供的全部功能都列为需求。

## 3. 布局与入口

**采用：** 桌面默认非模态并排，可调宽；窄屏进入完整工作区。保留现有工作台的业务表单，助手不遮住主要操作、不强制接管焦点。

头部最多两个紧凑层级：第一行为AI助手身份、新会话、更多、收起；第二行为当前主题与可见“历史会话”。历史浮层承载搜索、归档筛选和有界翻页；改名、归档／恢复、任务记录与展开工作区放入单层中文菜单。

**不直接采用：** 一开始就增加第三条全局导航、第二个独立历史系统、多模式切换按钮组或比较两个模型的双聊天面板。参考库支持并不证明当前员工需要。

侧栏仍允许操作主页面。带搜索的历史浮层、动作菜单和Tooltip需分别使用合适的语义与键盘行为，不能把有输入框的内容标成Tooltip。只在真正的模态确认／详情框中限制焦点；Esc逐层关闭最上层浮层，不同时收起整个助手。

## 4. 新会话、输入与上下文

| 场景 | 项目方案 | 避免的问题 |
|---|---|---|
| 新会话空态 | 简短说明能做什么、写入需确认；2～3个合法示例 | 既没有引导，也不做长篇欢迎页 |
| 点示例 | 只填入输入框，由用户发送 | PatternFly示例可立即发送；本项目可能产生模型费用／取数，保留主动提交 |
| 输入 | 一个边框内组织上下文标签、文本和紧凑“发送”；保留Enter换行、Ctrl／Cmd+Enter及IME保护 | 为追求熟悉外观贸然改变已建立的快捷键习惯 |
| 任务进行中 | 可起草下一条，不自动排队、不并发提交同会话 | 发送回执覆盖新输入或自动重复执行 |
| 会话切换 | 页面内存草稿按会话隔离；离开提示 | 外观改造丢掉上一轮已修复的草稿保护 |
| 页面关联 | 仅展示实际关联枚举，小标签可移除和恢复 | “关联人员页”被误解成已读取整个页面、所有人员或隐藏字段 |
| 历史记忆 | 明确当前为有界服务端续问，权限变化会隐藏旧内容 | 营造永远记住全部历史或全企业共享聊天的假象 |
| 附件／语音 | 暂不显示入口 | 只有图标却没有安全上传、权限和处理闭环 |
| 服务未就绪 | 明确未启用／配置问题；仍能查看允许的记录 | 绿色“配置已就绪”被误当真实模型连接已验收 |

### 脚注与透明性取舍

不把“减少说明”理解成完全取消AI和资料边界。建议保留一行低强调的“AI辅助 · 以实际回执为准”，首次空态说明获准资料与确认规则，详情入口提供数据范围和记忆解释。错误、缺数和写入后果仍就地显示。该脚注是本项目候选文案，不构成自动法律合规承诺。

不照抄每条消息一大段免责声明，也不为了省一行让用户无法辨认AI输出。正文仍使用事实式表述，避免“我已替你处理好一切”等无回执承诺。

## 5. 消息、图标与视觉

- 用户消息使用轻背景，助手正文开放排版；角色有可访问语义，不靠人像头像模拟真实员工。
- 复制等就近、低风险小工具使用统一SVG＋中文Tooltip；改名／归档等在菜单内保留中文，不要求员工记一串图形。
- 最后一条完成回复显示低强调动作；历史回复hover／focus-within显示，触屏提供直接可达入口。预留动作空间或不挤动正文，避免悬停时消息跳动。
- 不常驻显示每条消息的模型请求数、token、重复“您／未关联页面／已完成”等元数据；有意义的时间和上下文可在详情中查阅。
- Markdown继续使用当前固定本地解析器与允许列表DOM。链接、长代码、表格和原文复制沿用安全与预算边界，不用模型HTML、远程图片或新图表脚本“美化”。
- 文本保留足够对比度。用留白和层级区分内容，不能通过把正文变淡、变小来降低视觉噪音。
- 18px图形、32px PC目标、40px以上触屏目标及正文65%面积均是项目候选值；缩放、窄高屏和长输入可以调整。不能拿这些数字替代任务可完成性。
- 不新增点赞／点踩占位：没有接收、隐私、处理和反馈用途闭环时，不宣称点击会训练模型。日后如做反馈，需说明收集什么、谁处理，而不是摆两个图标。

视觉样式限定在助手组件范围，复用现有色彩／字体／弹窗，不全局覆盖button、form、table；避免把后台业务列表和Markdown表格一起改坏。

### 5.1 推荐视觉语言与层级

方向是紧凑、安静的业务工具：保留工作台品牌色，使用中性底色、清楚的正文和少量语义色。以下是项目设计决策，不声称来自某库的强制规格。

| 层级 | 视觉处理 | 不采用 |
|---|---|---|
| 框架 | 整体一块平面；头部／输入区必要分隔，桌面并排边界清楚 | 聊天面板内再套多层大阴影卡片 |
| 主内容 | 用户问题轻背景靠右，助手内容靠左、默认无外框；长文最大宽度受控 | 每段文字、每次读取都一张描边卡片 |
| 主要动作 | 发送／当前明确审批采用既有品牌色与清楚文字 | 同时高亮新建、搜索、刷新、复制等所有按钮 |
| 辅助动作 | ghost样式、hover轻背景，统一图形／点击区 | 常态一排实心或描边按钮，各自大小不同 |
| 状态 | 当前活动轮显示真实状态；警告含文字与图形，重要状态就地呈现 | 只有红绿点、无依据的“成功”绿勾或闪烁动画 |
| 输入 | 一个整合容器，页面标签与文本有清楚间距；聚焦状态突出当前输入 | 每条提示独立占行、按钮外置为第二张卡片 |
| 字体 | 沿用系统中文字体及既有字重，正文14～15px；元数据12px，保留对比度 | 引入新Web字体、用等宽字显示普通回复，或靠过小文字省空间 |
| 动效 | 浮层与hover短反馈，减少动效偏好优先；不对已完成正文补打字动画 | 为静态工具引入GSAP、模拟流式输出、跳动的高度变化 |

品牌色来自当前产品变量；不在助手CSS另写一套固定蓝紫主题。普通正文沿用高对比文本，次级元数据用现有muted变量并核验对比度；错误／警告复用全站语义色。边框、间距、圆角、焦点环成为共享token，不给每个消息部件发明不同值。

布局选型：完整工作区内容可围绕约760～820px候选阅读宽度，侧栏不额外嵌套窄列。中文、数字表格和代码分别测量，不套用仅适用于英文的固定字符数。普通消息间距大于元数据与正文间距，以层级代替边框数量。

### 5.2 组件边界与交互契约

| 组件 | 消费的数据／事件 | 必须维持的边界 |
|---|---|---|
| AssistantHeader | 当前主题、显示模式、新建／历史／更多／收起 | 不复制授权；收起不取消任务 |
| ConversationPicker | 本人列表、q、归档、游标与版本 | 10项分页、明确空／错／加载；搜索后重置旧游标，不能保留错配结果 |
| Composer | 会话内存草稿、页面枚举、受理状态 | IME、稳定request_key、等待期间新输入保留；不自动排队 |
| MessageActionBar | 原任务ID、可复制原文、终态 | 原文复制／HTTP降级，不支持的动作不展示 |
| ToolReceiptGroup | 实际回执数组、可靠摘要、覆盖标记 | 不猜成功；未知类型安全回退；不折叠必读结果 |
| ApprovalCard | 后端pending、ticket、version、完整预览 | 人决定、服务端校验；过期／已处理不能再批准 |
| TaskStatus | 当前服务端状态、写入在途、取消与错误类别 | 不读模型正文来推断状态，不生成任意进度 |
| Shared UI primitives | 显式icon、label、交互状态、焦点触发点 | 与原业务页共用Tooltip／确认／详情原语，不复制业务处理 |

这些是高内聚职责，不表示必须增加八个文件或引入组件框架；按现有模块组织拆分，避免仅为命名制造空层。更新仍以任务ID保持稳定DOM，不能为了套新组件恢复整块replaceChildren。

## 6. 工具、提案与实际结果

| 信息类型 | 默认显示 | 原因 |
|---|---|---|
| 模型解释 | 可读正文，明确AI性质 | 便于理解；不当实际写入证据 |
| 普通只读工具回执 | 小摘要＋“工具回执（N条）”可展开 | 减少重复卡片，N来自实际回执数组；不是成功业务数量 |
| 带业务影响的写入回执 | 服务端可证明的对象、结果和版本摘要；无可靠摘要时展开原回执 | 不能仅保留AI说“已完成” |
| 待批准提案 | 默认展开，显示操作、对象、变化、完整预览入口和批准／拒绝文字 | 用户需要理解自己批准什么 |
| 大预览未完整展示 | 明确截断及原完整详情入口 | 不让精简UI诱导在未展示内容上批准 |
| 缺数、部分覆盖、部分成功 | 结果附近明确标出 | 不藏在JSON，不能把当前页或部分聚合称全量 |
| 凭证、未获准数据 | 不显示／不复制／不发模型 | UI简化不扩展安全边界 |

摘要只能由现有可信结构化字段与服务端状态派生，不由模型决定“成功”“已确认”或颜色。未知类型保留通用安全详情，不为每个业务字段写死专属卡片，更不将图标点击映射为任意工具路径。

审批保留服务端本人归属、版本、ticket和过期检查。历史卡片或已决定卡片不能再次出现可执行批准按钮；模型文本里的“批准”不产生按钮或有效决定。

### 确认弹窗的边界

已存在的“提案卡＋确认弹窗”可能重复表达，但风险分级尚未成为可信契约。此次视觉改造不顺手删除原确认机制。先复用现有中文确认框，检查对象、动作和后果是否清楚；若后续要对普通写入改为一次显式卡片确认、仅对敏感动作二次确认，另行核查权限／操作风险和完整链路，不能仅按前端图标或模型描述判风险。

## 7. 执行反馈与恢复矩阵

| 实际状态 | 用户可见说明／动作 | 明确不能做 |
|---|---|---|
| 正常同步、idle | 不常驻占高横条，读屏状态按需更新 | 每轮轮询播报相同“已同步” |
| queued／running | 一条简短状态；状态来自服务端，允许起草 | 假百分比、虚构工具阶段、推理正文冒充审计 |
| awaiting_confirmation | 明显的待处理卡及文字动作 | 收进普通回执或更多菜单 |
| 批准决定已记录 | 等待执行回执 | 把“已批准”等同于“操作成功” |
| cancel_requested | 已请求停止、已完成操作不会回滚 | 关闭面板被当作取消；停止被当作撤销 |
| 读取网络故障 | “重新连接”只读恢复快照 | 通用重试重新启动模型或重放写入 |
| 写入回执未收到／结果未知 | 持续提示，查看实际任务／数据 | 提供“再试一次”主按钮 |
| 401／403 | 原授权处理／重新登录指引，清除不该继续显示的内容 | 仅隐藏按钮、保留旧敏感正文或绕过权限 |
| 409版本／提案冲突 | 刷新后重新核对 | 自动换版本后替人批准 |
| 模型不可用／预算耗尽 | 说明限制；引导有权限的原页面／任务详情 | 虚构成功，或默认付费无限重试 |
| 中断／服务重启 | 原记录核对，不恢复执行 | 把旧确认自动用于新任务 |

PatternFly文档中的流式停止用于停止输出；本项目取消可能发生在受控写入期间，必须使用更准确的“停止任务／已请求停止”，保持现有在途判定。当前没有SSE／逐字输出，不为视觉换肤顺带增加长连接；后续如引入，独立处理断线游标、权限撤销、背压和事件去重。

关闭助手后不自动取消任务。当前缺乏持续推送／全会话未读契约时，不伪造未读数和“刚刚已完成”提示；可保留任务记录核对入口。新会话不意味着旧任务回滚，必要时用一次短提示说明，不能反复弹模态阻拦。

## 8. 无障碍与稳定交互

1. 主工作台、助手消息、输入区及历史选择有清楚名称；正常侧栏不使用aria-modal，也不全局锁定Tab。
2. 图标按钮用原生button／a与明确名称；导航保持链接语义。Tooltip只解释，不承载菜单、审批影响或必读错误。
3. 历史浮层内有输入与筛选，应采用匹配的对话／表单语义；不要把所有浮层统一标成menu。使用真实menu角色时完整实现对应键盘行为。
4. 打开／关闭浮层有明确焦点路径；确认复杂表格可先聚焦标题，关闭返回触发点。Esc只关闭顶层，不连带收起侧栏。
5. 悬浮动作同时支持focus-within；不能让可聚焦按钮既透明不可见又永远不显示，不能使用aria-hidden隐藏可聚焦节点。
6. 自动轮询不抢焦点、不重建未变化消息；阅读历史、展开卡片时不强制追到底部。需新内容提示时用“回到最新”。
7. 固定头部和输入区不能遮住被Tab聚焦的链接／批准按钮；缩放200%、长标题、长中文和低高度窗口均要检查。
8. 保留当前HTTP无Clipboard／randomUUID环境、IME组合输入与系统减少动效设置的兼容；触屏不依赖Tooltip完成任务。

这些是实施要求，不是本轮已通过的无障碍认证。自动化只能覆盖其中一部分，读屏、认知负担和实际理解仍需人工测试。

## 9. 工程与功能范围

### 可以直接进入下一轮实现

- 头部与会话管理重组，减少重复按钮／横条。
- 统一显式IconButton、Tooltip、轻量动作栏和浮层关闭／焦点行为。
- 示例仅空态，输入区内聚；保留内存草稿与服务端权威历史。
- 普通结果渐进披露，审批／异常／关键写入结果保持显著。
- 根据现有状态显示准确的恢复动作，文案不夸大执行结果。

### 需项目验收后再定参数

头部是否一行或两行、浮层宽度、各档面板宽度、元数据默认显隐及正文面积；用可操作原型与业务任务评估，不再靠“某产品也这么做”直接定死。

### 本轮不扩张

语音、附件处理、模型切换、会话分享／删除、反馈收集系统、编辑历史、任务分支、自动重试／排队、跨设备草稿、后台未读推送、SSE、任意生成UI与模型推理展示。它们需要对应数据／权限／运行生命周期，不能以一个按钮纳入视觉改造。

### 实现方式

沿用现有原生JS／CSS和服务端BFF。原IconAction增强器只服务表格，不应直接扩展成靠中文正则猜测所有动作；提取显式图标／名称工厂。共享的是样式、状态展示与交互原语，不是复制审批、身份或工具执行逻辑。

图标源码如采用第三方库，只选择必要SVG并保留许可证；不因十个图标引入整套大型UI和新构建链。不得复制第三方品牌、头像或完整演示资产到交付包。
