# 登录与模型接入通用性整改

基线：86a6ced。按隔离复现推进，不读取真实凭证、不调用真实付费模型。

## 方案与顺序

1. 登录 Cookie 按配置的公开地址生成稳定实例命名空间，覆盖普通登录、再次认证、退出与授权停用。只清理本实例事务，保留 PKCE 与浏览器绑定。旧未隔离 Cookie 不作为新实例凭据，升级后重新登录。
2. 连接测试使用明确独立预算，不再借用数据库操作超时；页面说明测试预算与实际业务请求超时的区别。
3. 内网 HTTP 模型：允许配置明确授权的内网端点；公网仍使用 HTTPS。服务出口与员工端配置分别验证，不依赖企业服务的 HTTP 演示开关。
4. 登录事务过期、重启失效、浏览器绑定不符统一呈现恢复页，提供本站重新登录入口；不重放回调、不放宽绑定。
5. 网关高级配置：研究 SDK 原生 header/query 接口及无密钥模式，复用既有加密凭证；禁止凭证明文混入普通参数或覆盖传输层保留头。覆盖三个协议、独立员工端及托管服务。

## 验收

先记录失败测试，再实现。验证跨实例与同实例多标签登录、失效恢复、防重放、模型测试预算；再验证网络策略、网关参数与无密钥请求。完整非 live 回归、独立 Agent 回归、类型与格式检查、契约和模板一致性；需要数据库／浏览器时使用隔离实例。真实供应商推理与现网部署不由合成测试替代。

## 当前进度

五项已完成源码实现与隔离验证：

- Cookie：按可信公开地址派生，含端口；普通登录、账号再次认证、停用当前授权和退出统一使用。恢复页使用现有页面组件、固定本站入口、不回显敏感回调。
- 预算：测试取 request_timeout、limits.seconds、30秒最小值，与 operation_timeout 解耦；服务状态和页面可见有效值。
- 内网：服务端显式地址授权可接RFC1918 IPv4 HTTP；员工端独立 allow_model_http 开关，保留公网HTTPS与解析后地址检查。内网域名／IPv6 HTTP不是本次员工端兼容承诺。
- 网关：三协议共用现有异步SDK，支持无密钥、自定义秘密头与结构化非秘密header/query；秘密不进入普通参数，仍复用加密存储。普通服务不依赖Agent包；两端边界验证保持独立并有对照测试，避免普通服务引入模型SDK。
- Web：鉴权模式与密钥必填联动；网关参数折叠显示，沿用统一输入样式；保留无JS人工选择密钥操作的回退。

## 本轮验证结果（2026-10-28）

- 非live完整回归：694通过、126个live测试明确排除。排除项不计通过。
- 独立Agent回归：60通过，包含三协议无密钥／自定义密钥头、宿主凭证隔离和真实loopback HTTP协议链路。
- 隔离PG与浏览器：4通过，覆盖配置生命周期、测试取消与收尾、无密钥网关保存／测试／启用／数据库重读、配置页交互。新增无密钥交互断言后另跑浏览器1项通过。
- 普通和Agent镜像分别构建并独立运行，通过正式迁移、初始化、就绪、未授权拦截、Host检查与关闭。Agent容器另通过HTTP合成供应商保存、测试、启用、任务、重启、停用。
- Ruff、服务／SDK mypy（121文件）、Agent mypy（10文件）、架构依赖、能力覆盖、技能静态检查、模板配置一致性、OpenAPI导出一致性通过。
- 曾失败的证据保留于本地runtime/usability-audit：原Cookie干扰、原预算截断；初轮遗漏文案／页面清单，浏览器缺安装包，以及新增集成测试错误假定共享夹具版本为0。已分别修正并回归；未靠重跑掩盖问题。
