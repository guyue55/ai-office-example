# 管理员模型配置闭环实施计划

**目标**：管理员在控制台管理服务端助手模型，普通员工仅使用；支持现有三协议，不复制模型运行时。

**架构**：元数据修订与密钥密文存PG，专用持久化Fernet根密钥由部署提供。所有入口复用应用操作、权限、契约和审计。保存草稿与显式应用分离；配置切换和任务受理由同一协调器锁串行，存在活动任务拒绝切换，失败保留原Runner。单进程约束不变。

**技术栈**：FastAPI异步、SQLAlchemy/PG18、Pydantic、cryptography Fernet、现有Jinja共享组件、现有三协议异步SDK。

## 决策与边界

- 一个托管连接；草稿修订不可覆盖，乐观版本拒绝旧页面提交。重复保存同版本返回冲突，不盲目重放。
- 初始来源为外部文件；草稿不覆盖它。显式启用托管修订后数据库成为来源；停用不会回退文件。重启恢复来源与活动修订。
- 密钥动作保留/替换/清除；响应、审计、预览及错误均无原值。加密根密钥不可复用会话密钥，丢失不能解密；随备份安全保存，首版不提供在线根密钥轮换。
- 托管模型出口由运维在service.json的agent_model_urls显式列出精确base URL，管理页面不能扩展出口；不自动探测供应商。HTTPS优先，loopback HTTP仅用于隔离验收。
- 配置管理仅HTTP/Web人工管理，不暴露给模型工具、MCP或员工SDK，避免秘密进入AI上下文；能力清单明确标识此范围。
- 真实连接测试必须明确确认可能计费；固定合成提示、无业务工具、单次请求、无自动重试，结果只返回通过/失败，不回显供应商响应。
- HTTP演示仍提示未加密，不承诺正式安全。当前实例、真实密钥与付费模型不在此次测试范围。

## 实施顺序

1. **契约与持久化**：新增model配置输入输出、两张表及0014迁移；read/manage/apply/test权限迁移只执行一次。
2. **秘密与出口**：独立加密适配器，受限根密钥读取、线程隔离；新装生成秘密，已有实例显式补配，禁止静默生成替换旧根密钥。
3. **应用生命周期**：保存/读取/应用/停用/测试，版本核验、脱敏审计、活动任务阻断和重启恢复；Runner绑定当前修订。
4. **入口与UI**：统一包装HTTP路由、控制台设置页、三协议表单、预算、密钥动作与确认；管理员未启用提示可直达。
5. **核验**：单测安全与格式；全新临时PG正式迁移，普通用户拒绝、秘密保留/替换/清除、409、失败保持原配置、活动任务锁及重启；三协议既有HTTP回归；浏览器验证无密钥回显与保存/启停闭环。
6. **交付**：生成契约、质量门禁、同步README/运行指南/设计与验收；本地提交，发布仍暂停。
