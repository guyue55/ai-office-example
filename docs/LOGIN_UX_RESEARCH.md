# 登录与认证体验研究及重构建议

日期：2026-11-05。结论：需要系统升级认证体验层；保留Keycloak受控认证流程，以继承主题为起点，避免另造登录表单。本文是调研与方案，不是主题改造或登录链路已完成验收的记录。

## 当前实现与实测证据

- 主题位于deploy/identity/themes/office/login，parent=keycloak.v2，仅覆盖CSS、品牌及三项标题文案；没有自定义FTL。
- 在独立匿名浏览器中从本地控制台发起新登录，未填写或提交账号密码。真实渲染使用PatternFly v5父样式及本地office.css/product.css，不能按最新PatternFly v6类名直接套用。
- 用户名有label及autocomplete=username，密码有label及autocomplete=current-password，父主题提供显隐按钮。这些应保留；不能据此宣称整个认证流程达到WCAG。
- 1440×900、390×844、320×640下未见全页横向溢出；390px下品牌标题将“台”挤到独立一行，用户名字段上边缘约454px。office.css的18vh顶部间距与48px品牌间距占用了移动首屏；软键盘是否遮挡尚未在真实移动设备验证。
- CSS仍使用较重阴影、强顶部蓝线及旧控件视觉，与当前中性工作台不一致。这是设计判断，不是认证故障。
- 中英文标题覆盖都由scripts/configure_template.py生成相同中文字符串。不能手改生成文件；中英文一致性修复需调整生成器并验证自定义品牌。
- 当前未找到专门覆盖此主题的浏览器测试。tests/ui-pages.json是应用Jinja目录，不包含Keycloak登录、首次改密和重新认证；两者不能混称全覆盖。
- 匿名截图留在忽略目录runtime/login-research。未复用对话中的旧授权链接，未读取秘密、回调或用户会话。

## 一手资料及适用条件

| 依据 | 对本项目的决策 |
|---|---|
| [Keycloak主题机制](https://www.keycloak.org/ui-customization/themes) | 继续继承父主题，覆盖布局/样式和必要内容；如改FTL，只覆盖最小模板并维护版本兼容 |
| [PatternFly登录设计](https://www.patternfly.org/components/login-page/design-guidelines/) | 清晰产品身份、登录任务、语言入口、错误与可用恢复路径；当前v5父主题不能直接复制v6组件 |
| [GOV.UK密码模式](https://design-system.service.gov.uk/patterns/passwords/)及[输入组件](https://design-system.service.gov.uk/components/password-input/) | 支持粘贴/密码管理器，显隐可键盘操作；密码策略由服务端配置，不按设计建议擅自修改 |
| [WCAG可访问认证](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum) | 不阻止自动填充、复制粘贴或增加记忆挑战；没有完整流程证据时不声称合规 |
| [Keycloakify源码](https://github.com/keycloakify/keycloakify) | 可用于复杂React主题和页面场景研发；本项目当前CSS继承足够作为首阶段，不因开源项目存在就新增构建链 |

## 目标设计

1. **布局**：桌面使用克制的单列认证面板，品牌与表单构成一组；不需要营销插画或大面积双栏。窄屏减少顶部留白，标题自然换行，短屏和长错误可正常滚动。
2. **信息**：明确企业/产品身份与“登录工作台”任务；保留语言选择但降低视觉权重。不添加当前实例未启用的注册、找回密码、第三方登录或“记住我”。
3. **输入**：标签常驻，账号与密码宽度对齐，保留autocomplete和原生提交；合理触摸尺寸、清晰焦点、可理解的显隐名称。不要默认把焦点送进密码框，也不阻止粘贴。
4. **反馈**：错误在表单附近且可感知，不区分“账号存在/不存在”；保留非敏感输入并清楚指出下一步。重复提交反馈不能提前禁用待序列化字段，不自动重试密码。
5. **视觉**：与工作台共享品牌色、文字层级、边框和圆角方向，但身份服务资源独立打包，不依赖工作台运行时或外部字体/CDN。
6. **动效**：不为认证流程加入GSAP编排；减少动态优先，避免表单自动漂移、长入场或加载时隐藏输入。稳定且快速完成登录比装饰更重要。
7. **国际化**：标题覆盖由品牌生成器统一产出真正的中/英文；名称仍为文字品牌，不把本轮改造扩展成任意Logo/favicons能力。

## 必须覆盖的状态

| 状态 | 重点 | 验证方式 |
|---|---|---|
| 正常登录 | 首屏布局、标签、自动填充、键盘、显隐 | 匿名真实渲染；密码管理器需人工检查 |
| 凭据错误/账号限制 | 通用错误、不泄露身份、明确恢复 | 专用合成账号隔离实例；不尝试真实用户密码 |
| 首次修改密码 | 新密码/确认、策略说明、错误与一致性 | 专用临时账号，不修改本人或在用账号 |
| 本人重新认证 | 保留当前操作上下文及原身份约束 | 隔离身份/浏览器绑定，不能跳过认证 |
| 登录过期/旧链接 | 新发起登录，不重放旧回调 | 独立短周期场景，保留服务端PKCE/绑定 |
| 邮件/OTP/通行密钥等 | 仅在实例实际启用时展示和验收 | 不因主题支持就声称企业已启用 |
| 无JS/窄屏/减少动态 | 核心表单可提交、内容不溢出 | 浏览器断点及真机软键盘；读屏另验 |

## 执行顺序与门槛

- 第一阶段：主题CSS重构与专用页面样本；真实匿名页面在1440/1024/768/390/320及短屏验证，查看计算样式而非只看CSS。
- 第二阶段：品牌生成器语言输出与必要文案，运行自定义品牌一致性/生成检查。不能改生成文件绕过运行足迹保护。
- 第三阶段：隔离Keycloak覆盖错误、首次改密、本人重新认证及过期恢复；测试明确禁止连接在用企业账号。
- 第二轮独立复核：比较布局与交互证据，检查焦点/错误关联、自动填充/粘贴、语言及父主题版本兼容；记录失败和未验范围。
- 最后同步AGENTS及账本，按任务文件提交。本轮调研没有修改主题、策略、真实账号或运行服务。
