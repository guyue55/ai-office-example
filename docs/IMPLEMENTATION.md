# 模板扩展与实施方法

本文件面向使用模板的新项目，说明实施顺序和边界。测试结果及未验收项见 [验收说明](ACCEPTANCE.md)，不将开发过程记录视为交付承诺。

## 推荐顺序

1. 阅读 README、AGENTS、架构与配置文档，明确服务端无 AI、客户端不直连数据库的边界。
2. 修改 template.toml，使用 new_project.py 生成独立项目；校验产品、命令、命名空间与生成文件一致。
3. 按 INSTALL.md 分别部署服务器与员工客户端，不向员工交付服务器秘密。
4. 先验证匿名连接、本人浏览器授权、实时权限、预览确认、版本、审计与失败恢复，再新增业务规则。
5. 企业扩展优先复用动态字段、权限组合和受控查询；新增业务技能不重复实现认证、契约或数据访问。
6. 在独立实例验证默认与非默认品牌、完整安装及重复执行、Windows／Linux 兼容和实际 AI 宿主发现。
7. 基于明确提交构建候选制品、验证摘要，验收后再单独执行发布。

## 扩展约束

不创建空行业模块，不把示例字段变为基座固定业务口径；多维聚合不代替跨容器语义定义。确认版本保持冻结，更正走新版本和再次确认。

修改公开产品配置不等于迁移既有实例身份；已有运行足迹时按独立迁移方案处理，不清除保护标记以绕过检查。

## 验证与记录

验证命令维护于 CONTRIBUTING.md；记录来源提交、环境、结果和限制，原始日志、账号、初始密码及数据库不得进入源码。只把可脱敏复核的结果写入项目文档。

模板更新不自动覆盖企业代码；升级应比较差异、验证迁移并保留恢复方式。
