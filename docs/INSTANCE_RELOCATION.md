# HTTP演示实例迁址维护

适用：已由本项目安装器创建、内置PG、保持原端口的HTTP演示实例。不是HTTPS证书迁移、外部数据库迁移、通用升级器或生产滚动部署方案。

## 为什么不能只改监听IP

公开地址同时关联服务public_url／issuer／audience、Keycloak hostname、Web回调、客户端受众及业务库身份来源。必须保持原realm、用户主体、角色和数据；员工客户端使用新地址后重新登录，不复制旧令牌。

依据：[Keycloak hostname](https://www.keycloak.org/server/hostname)、[代理配置](https://www.keycloak.org/server/reverseproxy)、[Admin REST API](https://www.keycloak.org/docs-api/latest/rest-api/)。本实现使用项目现有Keycloak版本及公开管理端点，不通过关闭issuer校验或伪造旧IP恢复访问。

## 使用

宿主只需本机Docker、Compose及Bash。辅助Python运行在官方Docker CLI容器，不安装宿主Python。候选镜像须已按项目门禁验证，与当前数据库结构相容；本入口不会自动执行结构升级。

```bash
# 默认只核对配置、原身份系统及数据库，不停服务、不迁移资料。
bash deploy/relocate.sh /srv/office-instance \
  --url http://192.168.10.20:19880 --listen lan \
  --image <已验证本地镜像>

# 明确维护窗口后执行；会结束该实例旧地址的全部登录会话。
bash deploy/relocate.sh /srv/office-instance \
  --url http://192.168.10.20:19880 --listen lan \
  --image <已验证本地镜像> --apply
```

`--listen`接受`lan`、`local`或明确内网IPv4；`lan`用于让迁址后的入口覆盖服务器所有当前内网地址，IP再次变化时不必重建端口映射。公开URL仍必须一致更新，因为HTTP演示的登录身份仍包含IP。不自动发现或更改其他实例，不支持同时改端口或切换HTTPS。不允许未完成账号操作或活动Agent任务跨越迁移。

流程：实例锁 → 原realm／主体／受众与DB预检 → 停写 → 两库逻辑备份并检查归档 → 保存原配置及文件属主权限 → 更新一致的服务、身份与网关配置 → 维护门后修改身份客户端和映射 → 结束旧会话并追加维护审计 → 比对业务数量及主体映射摘要 → 就绪、公开健康与OIDC发现核验 → 开放入口 → 再次核验。

维护门仅开放健康检查和OIDC发现，不开放登录与业务操作。进入尝试开放入口的阶段后，不允许自动恢复旧数据库快照，避免覆盖新写入。

## 备份与失败

实例下relocations/<运行ID>/保存两份dump、原配置、文件属主权限、基线及阶段结果，目录700、备份600，不进入Git或员工包。密码不输出、不重置，秘密文件保持原引用。迁移更新身份链接来源，旧授权记录保留原issuer并标记结束；不改写用户ID、密码、项目数据或历史审计。

失败时保留阶段标记并停止业务、身份及网关。不可直接再次apply叠加。尚未尝试开放写入时，可显式恢复同一次失败迁址：

```bash
bash deploy/relocate.sh /srv/office-instance --restore <失败运行ID> --apply
```

恢复两库及原配置后仍保持停写；原地址可达性要先确认。已完成或已尝试开放的迁址拒绝此恢复入口，须按实际新增数据另行评估。备份、失败日志和恢复资料不自动删除。

## 客户端与长期地址

迁址结果只含公开地址，不含凭证。更新原交付公开配置中的OFFICE_PUBLIC_URL／监听地址及已安装客户端connection.json的service；配置来源必须由管理员确认。使用匿名connection-check验证新入口，再由本人完成浏览器PKCE授权和whoami检查。AI不得读取或复制旧钥匙串令牌。

本入口不会扫描员工电脑并自动修改其他企业配置或全局CLI。正式HTTPS部署应使用经IT确认的稳定内部域名并默认`lan`监听，服务器IP变化只更新DNS；显式IP迁址仅用于没有稳定名称的HTTP验收兜底。不要把员工电脑经常变化的地址作为正式入口，详见[网络监听与稳定入口](NETWORK_ADDRESSING.md)。

## 本机实际记录（2026-10-27）

原IP已不在网卡上，独立验收栈完成显式迁址并更新UI镜像。配置、两库备份、身份主体、用户数量、人员／角色／项目／记录数量及映射摘要核验通过；新入口健康及CLI匿名连接检查通过。

首轮因维护门未放行公开OIDC发现而核验失败，没有开放业务写入；已真实恢复业务与身份库及原配置，修正门控回归后再迁移成功。两次运行及恢复资料均保留在受限runtime中，不将首轮失败写成成功。现场本人登录与客户端身份验证另记验收结果。

本人完成登录后，已在新地址真实核验Web会话：原管理员身份、20项有效权限及原角色保留；人员账号详情可从抽屉读取身份系统中的原登录账号，新建员工表单可正常打开，默认普通员工授权及首次使用方式可见。审计页同时保留原初始化／登录记录，并显示新的「系统维护／迁移实例访问地址」记录及本次新会话记录。

真实页面的悬浮助手可打开和收起侧栏；当前实例未配置模型，明确显示不可用并禁用发送。没有发送模型请求、创建员工或修改权限。截图仅保存在忽略的本机runtime目录。客户端本轮仅验证匿名连接，未验证CLI本人授权或whoami；不能将Web登录通过等同于CLI身份验收通过。

## 默认局域网监听后的本机复验（2026-10-29）

机器地址已由`192.168.1.4`变为`172.16.170.83`，原实例端口仍发布到旧IP，lo和当前网卡均不可达。只读预检通过后，以`--url http://172.16.170.83:19880 --listen lan`执行保留身份和业务库的迁址。新端口映射为`0.0.0.0:19880`，旧地址会话结束并生成备份，需本人重新登录。

真实核验：`172.16.170.83`根路由303到同源控制台，健康检查200；`127.0.0.1`与`localhost`经308转到唯一登录主地址，避免在Keycloak回调前产生不同Cookie来源。公开OIDC issuer与authorization endpoint均使用主地址。部署相关回归、`ruff`与Shell语法检查通过；临时nginx容器真实验证了`0.0.0.0`发布后lo和当前内网IP均可访问。

随后停止Docker Desktop进行真实恢复测试：根目录`./restart.sh`检测引擎不可用，自动启动Docker、发现当前唯一实例与`en0/172.16.170.83`，密码和地址未变时恢复容器并重启gateway/service，健康检查200。脚本不依赖DNS；IP变化走迁址，多地址交互选择登录主地址。

本实例仍是显式HTTP验收模式，登录身份仍含IP；本次只恢复当前可达性。正式IP无关性要求内部DNS名称和HTTPS，按[网络监听与稳定入口](NETWORK_ADDRESSING.md)迁移。
