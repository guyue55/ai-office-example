# 服务端 UI 优化：现状、方案与逐项验收

## 共享详情阅读体验再审查

- 研究：[Carbon Modal](https://www.carbondesignsystem.com/building-blocks/core/components/modal/guidelines)强调按内容选择尺寸、正文内滚动；[Tabler](https://github.com/tabler/tabler)作为管理台组件开源对照。本轮保留原生dialog，不引入Bootstrap或动画依赖。
- 原共享详情统一620px，权限与角色表也受限，正文65vh与外层85vh各自约束。含表格时改为最大960px，短表单保持紧凑；打开时纵向flex，标题不收缩、正文滚动，总高度采用动态视口限制。没有修改授权、提交、分页或无JS详情机制。
- 二次复核：新增合成长表用例覆盖1440×900、390×600及844×390，检查正文可滚动、关闭入口在视口内、关闭后隐藏、焦点归还及零写入。修改前基线36项通过；修改后页面目录与交互状态37项通过。合成模板浏览器证据不代表真人账号或模型验收。
- 这是共享详情组件的一批改进，不代表全站新一轮审查完成；列表、设置与助手仍需按任务分别复核。本批源码尚未更新到现有运行实例。

日期：2026-11-05。范围是模板项目的 Web 控制台和智能助手。历史升级见 [UI_UPGRADE_PLAN.md](UI_UPGRADE_PLAN.md)，其中当时的完成状态不代表本轮现状。

## 已核对的基线

- 当前 tests/ui-pages.json 登记 24 个页面模板；Jinja 服务端渲染、原生 CSS/JS、按服务端权限显示入口。页面目录的隔离浏览器测试覆盖五种宽度、可访问名称、横向溢出和部分助手行为；它不证明真实身份、数据库、模型或人工可用性。
- 390×844 的模型设置页滚动到底时，固定助手入口与附加请求头输入框相交约 120×49 px。根因是入口固定在视口右下角，而有入口的页面末尾没有对应的滚动余量。
- 390 px 的人员、审计、客户端授权等管理表只显示左侧部分列；完整列在局部横向滚动区。截图中没有明确的滑动提示，右侧操作的发现成本偏高。这是可用性判断，尚无真人任务测试证据。
- 模板主色是蓝色（template.toml），但共享主按钮悬停规则写死了青绿色。修复前的样式规则与品牌配置冲突；修复后浏览器计算的默认背景为 rgb(37, 99, 235)，悬停背景保持同色相并加深。此处只修复共享悬停色，不把自定义品牌的所有对比度视为已验收。
- 旧 [UI_THEME_CHATGPT_REFERENCE.md](UI_THEME_CHATGPT_REFERENCE.md) 是双主题构想；当前样式仍是单套变量，不能写成已实现深色模式。

## 执行顺序与证据门槛

1. **已复现的共享问题（已实施）**：仅在显示助手入口的页面增加末尾滚动空间；在使用 management-table 的页面添加窄屏横向滚动提示和可聚焦、具名的滚动区；主按钮悬停色跟随品牌主色。验收：390×844 模型输入框与入口不相交；24 页五种宽度无全页横向溢出；可见管理表有提示，并能聚焦后以方向键横向滚动；默认蓝色品牌按钮悬停不跳成青绿色。完整助手工作区和无助手权限页面保持原布局。
2. **页面分组复核（本轮隔离部分完成）**：六组 24 页已逐页渲染并检查五种宽度、字段名称与横向溢出；账号、表单、助手工作区与页面状态另有浏览器回归。此证据不能覆盖真实身份、数据库、模型及真人可用性；后续只在对应专用实例核验这些链路。
3. **视觉体系与主题（本轮决定）**：保留现有 Jinja/原生 JS、浅色品牌与信息层级，仅修复实测的共享视觉问题。旧深色模式草案和 GSAP 动效没有明确的体验缺陷或验收目标支撑，本轮不引入；如后续选定跨主题或新框架，再独立设计令牌、授权状态和回退。
4. **交付验证（本轮本地完成）**：格式/静态检查、页面目录、相关浏览器和 Web 回归已执行。真实账号、付费模型、在用部署和发布未作为本轮本地 UI 结论的证据；后续环境验收按各自授权和专用实例单独开展。

本文件是本轮执行台账。完成的是现有 UI 的针对性优化和隔离复核，不等于全站视觉重设计或正式部署完成。

## 用户反馈后的复核与修复

- 复现：1440px 下人员页位置栏 y=32px，助手工作区 y=22px。专属 padding-top 覆盖共享 main 间距；删除覆盖后，五种宽度的位置栏 x/y 基线检查通过。桌面预留稳定滚动条空间，减少长列表与固定高度工作区切换时的横向跳动；窄屏沿用原滚动行为，避免改变既有浮动入口避让。
- 实例故障：本轮新 Docker 身份库与旧本地身份管理客户端配置不匹配，真实只读搜索复现 identity_unavailable；为当前开发实例独立配置管理连接后，搜索与账号详情读取均成功。此为实例初始化遗漏，不说明所有业务页面均有同一缺陷；开户、密码等真实写入未执行。
- 共享反馈：error.html 的原因缺少共享抽屉识别的语义标记，导致安全的业务原因被通用 HTTP 提示替代。增加 alert 标记，沿用文本提取和 500 字符限制；后备提示明确持续失败应联系管理员。新增浏览器回归使用真实错误模板验证显示、重试恢复及零写入。
- 新的布局基线断言在修复前实测失败（差 10px）；修复后页面目录和新增错误恢复用例通过。扩大浏览器检查时曾因全宽度稳定滚动条处理触发移动端入口遮挡断言，调整为仅桌面应用后复验通过。没有用动效掩盖布局错误，也未引入动画依赖。
- 边界：真实服务当前仅验证只读身份管理适配器和就绪端点；完整浏览器真人登录、开户写入、密码重置和真实模型仍须分别验收。原全页面合成通过记录不代表这些真实流程已通过。
- 最终验证：扩大检查首轮 32 通过、1 失败（上述移动端遮挡）；修复滚动条适用范围后，失败的全页面目录用例和新增真实错误模板恢复用例均通过（2 通过）。其余 32 项覆盖共享状态、账号流程和助手工作区；最终 Ruff、差异空白检查及本地 ready=200 通过。未把首轮失败算作通过。

## 列表信息密度与助手视图偏好复核

- 人员列表直接展示前三项关联角色及总数，增加账号维护方式；权限集列表展示前三项权限名称和关联角色及总数。超过三项明确标记“前3项/共N项”；较长名称省略，可通过共享提示查看这三项的完整文字。详情仍保留完整关系及分页。
- 权限目录将编码从名称下方独立成列；用途与范围限制为两行，共享提示提供完整说明和键盘访问。
- 摘要来自当前页对象的批量关系查询，以数据库窗口函数限制每对象三项；没有逐行查询、远程身份请求或按角色名称判断权限。输出模型新增可选列表字段并重新生成OpenAPI；不涉及迁移。
- 访问完整助手页会调用open和save；原save用full||可见状态写入侧栏open=true，导致下一业务页自动展开。修复后完整页仅更新会话ID，保留先前侧栏open与width；业务页侧栏仍由用户开关控制。
- 验证：隔离PG摘要测试1通过；页面目录与助手工作区浏览器3通过；共享提示与页面复核等20通过；类型检查125文件、架构检查、Ruff与契约一致性通过。新增目录断言进一步核对摘要和权限编码列。均不代表真实模型或真实账号写入已验收。
