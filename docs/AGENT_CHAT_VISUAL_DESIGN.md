# Agent 聊天窗：视觉简化与控件分级方案

日期：2026-10-26；源码基线：`2e19f71`；适用仓库：ai-office-example，codex/agent。

状态：调研与设计，尚未修改界面。用户本轮要求调研专业方案；本文补充上一轮功能实现后的视觉评审，不把功能回归通过等同于交互与视觉成熟。

## 1. 判断与证据边界

当前问题主要是信息架构：把会话管理、运行状态、说明、消息操作和输入辅助同时常驻在窄侧栏。仅替换图标仍会留下过多层级，应先分清常态、按需和必须可见，再统一图标及悬浮提示。

本次核对了当前HTML／CSS／JS及上一轮隔离Chrome截图 `runtime/agent-research/browser/assistant-chat-ux.png`。该截图为合成安全测试数据，不是客户资料；它是基线验收产物，并非对当前在用服务的实时截图。没有操作用户登录、模型、容器或部署。

在该1600×1000截图中，聊天窗上方约300px、下方约270px用于管理和输入辅助，消息区仅约430px。该数值是这张截图的粗略观察，不代表所有尺寸；后续用DOM边界复测。

公开产品文档和设计系统可证明具体模式有成熟参考，不能证明市场占有率或某个布局普遍最优。本项目属于业务工作台中的可执行助手：应减少普通阅读噪音，同时保留审批、缺数、权限和结果未知的显著性。

## 3. 当前问题与具体处理

| 当前内容 | 建议位置／显示时机 | 取舍原因 |
|---|---|---|
| 智能助手标题＋说明＋另行会话选择 | 合为紧凑头部：当前会话标题＋下拉 | 头部主要传达当前主题；“助手”语义仍保留在可访问名称中 |
| 新会话文字大按钮 | 头部ghost图标，中文Tooltip“新会话”，采用书写／新建会话图形 | 高频动作常驻；不使用容易和附件混淆的孤立加号 |
| 改名、归档／恢复 | 当前会话更多菜单，中文文字选项 | 有上下文和后果，菜单里文字比一排图标易懂 |
| 搜索输入＋搜索按钮 | 点击标题打开会话选择浮层，搜索位于该浮层 | 使用聊天时不常驻搜索工具栏；保持显式搜索／Enter，避免每键请求 |
| 归档勾选、更多会话 | 会话选择浮层内的筛选和分页 | 与查找历史在同一闭环；保留10条和游标，不假装已取全 |
| 独立任务记录 | 更多菜单“任务记录” | 保留审计／兼容入口，普通对话不需要持续展示链接 |
| 更新于、本人会话 | 标题详情或会话列表次级信息 | 当前对话不重复显示“本人”；不把时间元数据放成独立横栏 |
| 展开全页 | 更多菜单“展开工作区”；若实测高频可恢复单独图标 | 首版优先缩减头部可见控件；全页时不显示无效入口 |
| 收起 | 侧栏头部方向明确的图标，Tooltip“收起助手” | 与停止任务彻底分开；全页不提供含糊关闭 |
| 重新加载 | 正常时不常驻；读取失败／轮询暂停时展示“重新连接”文字动作 | 只有实际执行状态读取，绝不重放模型任务或写入 |
| 选择会话／已同步等正常提示条 | 空态内容或无视觉占高的读屏状态区 | 删除重复正常文案；处理中以一条简短状态显示 |
| 每条消息的“您·页面／状态” | 用户问题保持轻背景；页面关联仅有值且确有意义时显示小标签；运行状态只挂当前活动轮 | 避免像日志列表；终态和技术信息进入结果详情 |
| 复制回复 | 18px图标＋中文Tooltip；历史消息hover/focus-within显示，最后一条完成消息低强调常驻 | 低风险动作图标化；生成中不让不完整文本误装完整回复；HTTP降级保留 |
| token／模型请求次数 | 回复“详情”中 | 业务人员默认关注结果；预算耗尽／截断等异常必须可见 |
| 多张工具回执卡 | 普通回执合为可展开“工具回执（N条）” | 默认阅读结论，按需核对证据；N来自真实数组长度，不宣称N项业务已成功 |
| 重复刷新业务页面说明 | 确有相关写入回执时提供一个上下文动作 | 不为只读查询显示刷新；不自动丢弃业务表单草稿 |
| 示例问题常驻输入区 | 新会话空态展示2～3项；有对话后移除 | 让空态负责引导，不让老用户每次承受额外高度 |
| 关联页面整行checkbox | 输入框内紧凑标签“仪表盘 ×”，有可见移除动作；取消后在上下文设置中可重新启用 | 用户能看到实际关联；仍仅发送页面枚举，不扩展抓取DOM或整页资料 |
| 快捷键、隐私、回执说明三段 | 快捷键进入帮助；首次空态保留简明能力边界；错误／禁用原因按需就地显示 | 不隐藏真正的授权／数据确认，不重复铺常识文案 |
| 发送 | 输入框右下角统一箭头图标＋Tooltip／可访问名称 | 清晰单一主动作；当前Ctrl／Cmd+Enter和IME保护保持 |
| 停止任务 | 活动轮状态行内“停止任务”文字按钮 | 保留范围与停止后果，不能与收起同义，也不强行变为发送按钮的无文字替身 |

不增加点赞、点踩、分享、语音、附件、编辑、重新生成等占位图标。后端不存在对应闭环时，不能为了模仿聊天产品展示假能力。“重新生成”尤其可能重放业务操作，当前不适合加入。

## 4. 推荐结构与状态

侧栏常态结构：

```text
┌───────────────────────────────────┐
│ 本月经营数据 ▾       [新建] [⋯] [收起] │  紧凑头部
├───────────────────────────────────┤
│                          用户的问题 │
│                                   │
│ 助手的结论、列表、表格               │
│ [复制]  [详情]                     │  低强调小图标
│ ▸ 工具回执（3条）                  │  普通回执按需打开
│                                   │
│ ……                                │
│                  [↓ 回到最新]      │  仅偏离最新时出现
├───────────────────────────────────┤
│ [仪表盘 ×]                        │  有关联才显示
│ 描述您希望完成的工作……             │
│                               [↑] │  单一发送主动作
└───────────────────────────────────┘
```

图示方括号是功能占位说明，实际高频低风险工具使用统一SVG，而非保留一排文字方框。更多菜单使用清楚的中文动作，不能嵌套第二层“更多”。新会话、更多和收起为侧栏常态3个头部图标；会话选择与搜索共用标题触发器。

| 状态 | 默认可见内容 | 不能隐藏的事项 |
|---|---|---|
| 首次／新会话 | 简短欢迎、能力边界、少量示例、输入框 | 未启用模型时说明真实情况，不给可发送假象 |
| 普通对话 | 头部、消息、紧凑输入框 | 当前上下文标签和有意义的结果覆盖说明 |
| 正在执行 | 活动轮一行状态＋停止任务 | 不能用动画或计时伪造阶段；仍可起草下一条 |
| 待批准 | 突出完整操作对象／摘要，拒绝／批准文字按钮 | 待批卡默认展开，确认范围、参数完整性、权限和版本校验均保留 |
| 部分／缺数／权限变更 | 结果附近的明确提示 | 不能把“不完整”藏在收起回执里，不误称全量 |
| 结果未知／中断 | 持续明确的结果提示和核对入口 | 不与普通完成一样弱化，不提供盲目重试 |
| 网络读取失败 | 就地原因＋重新连接 | 只重新读状态；已批准任务与实际写入不自动重发 |
| 正常完成 | 主要结论、轻量动作及可展开回执 | “收到回执”不自动等于“业务成功” |

普通结果可以渐进披露；未批准、结果未知、权限变化、大结果预览不完整等安全相关信息保持直接可见。

## 5. 图标、Tooltip与视觉约束

以下为本项目设计目标，不是上游统一强制尺寸：

- 间距用4／8／12／16／24px；头部48～56px，若标题另占一行则总高不超过104px。
- PC图形18px、点击区32px；控件之间至少4～8px。触屏提高到40px以上。图形线宽、基线、前景色一致。
- 图标按钮默认透明、无粗边框，hover才显示轻背景，focus-visible有清楚轮廓；不靠不同Emoji／Unicode字符当图标。
- 消息区正文14～15px、行高约1.65；元数据12px。正文不继续降低对比度来“变干净”。
- 用户消息轻背景、助手正文开放排版；普通查询与工具回执不重复套多层卡片。审批／异常用克制的边框和语义色，不依赖颜色单独区分状态。
- 输入框整体一个边框，内部包含关联标签、文本和发送；去掉外围多段说明与重复横线。高度按现有草稿自动增长能力控制。
- 普通idle会话在420×900视口，目标消息区至少占助手高度65%；长输入、审批和错误状态分别测，不通过裁剪文字强行满足比率。
- Tooltip须同时响应鼠标与键盘焦点，Esc关闭，可移入提示区域、不闪烁；作为说明而非菜单，不能放可点击选项。
- 图标自身始终有可访问名称，不把title属性当唯一无障碍标签；历史消息动作在focus-within时显现，触屏无需悬浮也能访问。
- 复用已有 `#ui-tooltip`、通知、确认和详情弹窗；现有实现主要增强表格动作，需要提取／扩展明确的IconButton工厂，不能把第二套悬浮提示堆进助手。
- 禁用原因、写入影响、撤销后果不只放Tooltip。可聚焦但不可执行的控件如采用aria-disabled，处理器也必须阻断执行。

## 6. 工程实施边界与顺序

这一轮视觉方案不需要改模型运行时、数据库、认证、执行／审批协议或新增前端框架。没有理由因参考React组件而迁移整个FastAPI原生工作台，也不需要GSAP。

| 阶段 | 涉及文件／组件 | 验收 |
|---|---|---|
| A：共用交互原语 | interactions.js、styles.css；IconButton与Popover／菜单能力按已有实现扩展 | 中文名称、Tooltip、键盘、触屏、Esc和焦点返回；不破坏现有人员／授权表格动作 |
| B：头部和历史 | _assistant_panel.html、assistant-shell.js、assistant.css | 搜索、切换、10项分页、归档／恢复、改名冲突及会话草稿仍闭环；主视图不常驻管理栏 |
| C：输入与空态 | 同一面板及状态派生 | 示例仅空态，输入标签可移除和恢复，快捷键／IME／草稿／HTTP标识保持；无附件占位入口 |
| D：消息和结果 | assistant-view.js、assistant-content.js、共用动作栏 | 复制hover/focus／HTTP降级、技术详情折叠、普通回执分组；待批和异常可见、不发生重复写入 |
| E：视觉与流程验收 | 既有隔离浏览器测试及独立截图 | 360／420／640侧栏、全页1440、窄屏390、长标题／中文／长代码／多回执、键盘／触屏、状态转换及65%阅读空间目标 |

优先顺序是信息结构→组件原语→排版与色彩→状态与可访问性→回归；不能只改CSS把按钮挤进更小空间。相关自动化断言以角色和中文可访问名称查找图标，不依赖可见文字CSS定位。

普通完成状态的技术信息折叠只是展示，仍保留服务器权威记录；不会改变history_hidden、detail_truncated、部分覆盖、逐次批准、幂等、取消、权限即时核验和写入未知的规则。
