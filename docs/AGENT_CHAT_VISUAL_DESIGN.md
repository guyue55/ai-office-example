# Agent 聊天窗：视觉简化与控件分级方案

日期：2026-10-26；设计修订：v0.3（完整链路核验后）；源码基线：`2e19f71`；适用仓库：ai-office-example，codex/agent。

状态：调研与设计，尚未修改界面。用户本轮要求调研专业方案；本文补充上一轮功能实现后的视觉评审，不把功能回归通过等同于交互与视觉成熟。

## 1. 判断与证据边界

当前问题主要是信息架构：把会话管理、运行状态、说明、消息操作和输入辅助同时常驻在窄侧栏。仅替换图标仍会留下过多层级，应先分清常态、按需和必须可见，再统一图标及悬浮提示。v0.2修正初稿中过度精简入口的取舍：新会话、历史会话与发送保留可见文字；当前标题不作为历史查找的唯一隐蔽入口。

本次核对了当前HTML／CSS／JS及上一轮隔离Chrome截图 `runtime/agent-research/browser/assistant-chat-ux.png`。该截图为合成安全测试数据，不是客户资料；它是基线验收产物，并非对当前在用服务的实时截图。没有操作用户登录、模型、容器或部署。

在该1600×1000截图中，聊天窗上方约300px、下方约270px用于管理和输入辅助，消息区仅约430px。该数值是这张截图的粗略观察，不代表所有尺寸；后续用DOM边界复测。

公开产品文档和设计系统可证明具体模式有成熟参考，不能证明市场占有率或某个布局普遍最优。本项目属于业务工作台中的可执行助手：应减少普通阅读噪音，同时保留审批、缺数、权限和结果未知的显著性。

## 3. 当前问题与具体处理

| 当前内容 | 建议位置／显示时机 | 取舍原因 |
|---|---|---|
| 智能助手标题＋说明＋另行会话选择 | 压缩为最多两行：助手与主要动作；当前标题与“历史会话”入口 | 保留明确AI身份和历史入口，去掉重复说明，不追求所有内容硬塞一行 |
| 新会话文字大按钮 | 头部紧凑的“新会话”文字动作，可配新建图形，不保留大号描边 | 主任务入口不让普通员工猜图标；不使用容易和附件混淆的孤立加号 |
| 改名、归档／恢复 | 当前会话更多菜单，中文文字选项 | 有上下文和后果，菜单里文字比一排图标易懂 |
| 搜索输入＋搜索按钮 | 点击可见文字“历史会话”打开选择浮层，搜索位于该浮层 | 不只靠无文案的时钟或标题箭头；保持显式搜索／Enter，避免每键请求 |
| 归档勾选、更多会话 | 会话选择浮层内的筛选和分页 | 与查找历史在同一闭环；保留10条和游标，不假装已取全 |
| 独立任务记录 | 更多菜单“任务记录” | 保留审计／兼容入口，普通对话不需要持续展示链接 |
| 更新于、本人会话 | 标题详情或会话列表次级信息 | 当前对话不重复显示“本人”；不把时间元数据放成独立横栏 |
| 展开全页 | 更多菜单“展开工作区”；若实测高频可恢复单独图标 | 首版优先缩减头部可见控件；全页时不显示无效入口 |
| 收起 | 侧栏头部方向明确的图标，Tooltip“收起助手” | 与停止任务彻底分开；全页不提供含糊关闭 |
| 重新加载 | 正常时不常驻；读取失败／轮询暂停时展示“重新连接”文字动作 | 只有实际执行状态读取，绝不重放模型任务或写入 |
| 选择会话／已同步等正常提示条 | 空态内容或无视觉占高的读屏状态区 | 删除重复正常文案；处理中以一条简短状态显示 |
| 每条消息的“您·页面／状态” | 用户问题保持轻背景；页面关联仅有值且确有意义时显示小标签；运行状态只挂当前活动轮 | 避免像日志列表；终态和技术信息进入结果详情 |
| 复制回复 | 18px图标＋中文Tooltip；历史消息hover/focus-within显示，最后一条完成消息低强调常驻 | 低风险动作图标化；生成中不让不完整文本误装完整回复；HTTP降级保留 |
| token／模型请求次数 | 回复“详情”中 | 业务人员默认关注结果；预算耗尽／截断等异常必须可见 |
| 多张工具回执卡 | 普通回执合为可展开“工具回执（N条）” | 默认阅读结论，按需核对证据；N来自真实数组长度，不宣称N项业务已成功 |
| 重复刷新业务页面说明 | 确有相关写入回执时提供一个上下文动作 | 不为只读查询显示刷新；不自动丢弃业务表单草稿 |
| 示例问题常驻输入区 | 新会话空态展示2～3项；有对话后移除 | 让空态负责引导，不让老用户每次承受额外高度 |
| 关联页面整行checkbox | 输入框内紧凑标签“仪表盘 ×”，有可见移除动作；取消后在上下文设置中可重新启用 | 用户能看到实际关联；仍仅发送页面枚举，不扩展抓取DOM或整页资料 |
| 快捷键、隐私、回执说明三段 | 快捷键进入帮助；首次空态保留简明能力边界；错误／禁用原因按需就地显示 | 不隐藏真正的授权／数据确认，不重复铺常识文案 |
| 发送 | 输入框右下角紧凑“发送”文字主动作，可配箭头 | 首版面向普通业务人员，保留可发现性；当前Ctrl／Cmd+Enter和IME保护保持 |
| 停止任务 | 活动轮状态行内“停止任务”文字按钮 | 保留范围与停止后果，不能与收起同义，也不强行变为发送按钮的无文字替身 |

不增加点赞、点踩、分享、语音、附件、编辑、重新生成等占位图标。后端不存在对应闭环时，不能为了模仿聊天产品展示假能力。“重新生成”尤其可能重放业务操作，当前不适合加入。

## 4. 推荐结构与状态

侧栏常态结构：

```text
┌───────────────────────────────────┐
│ 智能助手       新会话  [⋯] [收起]   │  主要动作
│ 本月经营数据             历史会话 ▾ │  主题与查找入口
├───────────────────────────────────┤
│                          用户的问题 │
│                                   │
│ 助手的结论、列表、表格               │
│ [复制]  [详情]                     │  低强调小图标
│ ▸ 工具回执（3条）                  │  普通回执按需打开
│                                   │
│ ……                                │
│                  [↓ 回到最新]      │  仅偏离最新时出现
├───────────────────────────────────┤
│ [仪表盘 ×]                        │  有关联才显示
│ 描述您希望完成的工作……             │
│                             [发送] │  单一发送主动作
│ AI辅助 · 以实际回执为准             │  简短、低强调说明
└───────────────────────────────────┘
```

图示为信息层级，不是已经验收的像素稿。保留紧凑的新会话、历史会话、发送文字；更多、收起、复制等采用统一SVG。更多菜单使用清楚的中文动作，不能嵌套第二层“更多”。会话历史共用一个选择浮层：侧栏及当前全页先复用，不因参考PatternFly就引入新的模态抽屉；如果未来全页确需常驻历史列表，再让同一列表组件支持内嵌模式。

| 状态 | 默认可见内容 | 不能隐藏的事项 |
|---|---|---|
| 首次／新会话 | 简短欢迎、能力边界、少量示例、输入框 | 未启用模型时说明真实情况，不给可发送假象 |
| 普通对话 | 头部、消息、紧凑输入框 | 当前上下文标签和有意义的结果覆盖说明 |
| 正在执行 | 活动轮一行状态＋停止任务 | 不能用动画或计时伪造阶段；仍可起草下一条 |
| 待批准 | 突出完整操作对象／摘要，拒绝／批准文字按钮 | 待批卡默认展开，确认范围、参数完整性、权限和版本校验均保留 |
| 部分／缺数／权限变更 | 结果附近的明确提示 | 不能把“不完整”藏在收起回执里，不误称全量 |
| 结果未知／中断 | 持续明确的结果提示和核对入口 | 不与普通完成一样弱化，不提供盲目重试 |
| 网络读取失败 | 就地原因＋重新连接 | 只重新读状态；已批准任务与实际写入不自动重发 |
| 正常完成 | 主要结论、轻量动作及可展开回执 | “收到回执”不自动等于“业务成功” |

普通结果可以渐进披露；未批准、结果未知、权限变化、大结果预览不完整等安全相关信息保持直接可见。

## 5. 图标、Tooltip与视觉约束

以下为本项目设计目标，不是上游统一强制尺寸：

- 间距用4／8／12／16／24px；头部48～56px，若标题另占一行则总高不超过104px。
- PC图形18px、点击区32px；控件之间至少4～8px。触屏提高到40px以上。图形线宽、基线、前景色一致。
- 图标按钮默认透明、无粗边框，hover才显示轻背景，focus-visible有清楚轮廓；不靠不同Emoji／Unicode字符当图标。
- 消息区正文14～15px、行高约1.65；元数据12px。正文不继续降低对比度来“变干净”。
- 用户消息轻背景、助手正文开放排版；普通查询与工具回执不重复套多层卡片。审批／异常用克制的边框和语义色，不依赖颜色单独区分状态。
- 输入框整体一个边框，内部包含关联标签、文本和紧凑发送文字动作；去掉外围多段说明与重复横线。高度按现有草稿自动增长能力控制。
- 普通idle会话在420×900视口，目标消息区至少占助手高度65%；长输入、审批和错误状态分别测，不通过裁剪文字强行满足比率。
- Tooltip须同时响应鼠标与键盘焦点，Esc关闭，可移入提示区域、不闪烁；作为说明而非菜单，不能放可点击选项。
- 图标自身始终有可访问名称，不把title属性当唯一无障碍标签；历史消息动作在focus-within时显现，触屏无需悬浮也能访问。
- 复用已有 `#ui-tooltip`、通知、确认和详情弹窗；现有实现主要增强表格动作，需要提取／扩展明确的IconButton工厂，不能把第二套悬浮提示堆进助手。
- 禁用原因、写入影响、撤销后果不只放Tooltip。可聚焦但不可执行的控件如采用aria-disabled，处理器也必须阻断执行。

## 6. 工程实施边界与顺序

这一轮视觉方案不需要改模型运行时、数据库、认证、执行／审批协议或新增前端框架。没有理由因参考React组件而迁移整个FastAPI原生工作台，也不需要GSAP。

| 阶段 | 涉及文件／组件 | 验收 |
|---|---|---|
| A：共用交互原语 | interactions.js、styles.css；IconButton与Popover／菜单能力按已有实现扩展 | 中文名称、Tooltip、键盘、触屏、Esc和焦点返回；不破坏现有人员／授权表格动作 |
| B：头部和历史 | _assistant_panel.html、assistant-shell.js、assistant.css | 搜索、切换、10项分页、归档／恢复、改名冲突及会话草稿仍闭环；主视图不常驻管理栏 |
| C：输入与空态 | 同一面板及状态派生 | 示例仅空态，输入标签可移除和恢复，快捷键／IME／草稿／HTTP标识保持；无附件占位入口 |
| D：消息和结果 | assistant-view.js、assistant-content.js、共用动作栏 | 复制hover/focus／HTTP降级、技术详情折叠、普通回执分组；待批和异常可见、不发生重复写入 |
| E：视觉与流程验收 | 既有隔离浏览器测试及独立截图 | 360／420／640侧栏、全页1440、窄屏390、长标题／中文／长代码／多回执、键盘／触屏、状态转换及65%阅读空间目标 |

优先顺序是信息结构→组件原语→排版与色彩→状态与可访问性→回归；不能只改CSS把按钮挤进更小空间。相关自动化断言以角色和中文可访问名称查找图标，不依赖可见文字CSS定位。

普通完成状态的技术信息折叠只是展示，仍保留服务器权威记录；不会改变history_hidden、detail_truncated、部分覆盖、逐次批准、幂等、取消、权限即时核验和写入未知的规则。

## 7. 反例复核与最终取舍（v0.2）

### 7.1 不能从流行外观直接推出可用性

[NN/g图标研究（2024）](https://www.nngroup.com/articles/how-to-test-digital-icons/)区分“认出形状”与“理解用途”，并要求分别验证发现性、可点击性等；其[图标可用性说明](https://www.nngroup.com/articles/icon-usability/)亦提醒单靠悬停标签会增加理解成本。它是研究机构自身的一手研究／经验，不是所有企业场景的统计证明。

[PatternFly聊天历史组件源码](https://github.com/patternfly/chatbot/blob/fb88211f7826d252999f384a4ce4a4edb7be10b8/packages/module/src/ChatbotConversationHistoryNav/ChatbotConversationHistoryNav.tsx)把历史、搜索、新建和会话菜单组织在一起，并按docked／fullscreen采用不同布局；其设计团队的[历史入口问题记录#795](https://github.com/patternfly/patternfly-design-kit/issues/795)专门要求更明显的历史图标或标题。这是成熟团队也会修正入口发现性的实例，不能据此声称其全部用户都失败。

据此修正初稿：历史入口保留可见文字，不依赖“点一下当前标题就知道”；新建与发送也保留短文字。复制等熟悉、低风险、就近消息动作才优先采用图标＋Tooltip。更干净主要靠移除重复管理栏、提示和卡片边框，而不是删除所有标签。

### 7.2 并非所有回执都能折叠

[GOV.UK Details](https://design-system.service.gov.uk/components/details/)明确不建议隐藏多数用户都需要的信息。[assistant-ui Tool UI](https://www.assistant-ui.com/docs/tools/tool-ui)把工具运行、需操作、错误与结果分开呈现。这支持本项目区分普通回执与必须处理的执行状态，而非套用普通问答消息气泡。

- 只读查询的技术回执、token明细与原始JSON可以默认折叠；重要业务结果和缺数／覆盖范围不能仅出现在JSON里。
- 新产生的写入结果先给服务端可证明的结构化摘要；没有可验证摘要时，默认展开相关回执，不能只留下模型结论。
- 待批准卡持续展开。批准已记录、正在执行、写入结果未知必须与“成功完成”分开。
- UI依然只呈现原后端动作，不让模型生成审批按钮、设定授权或决定成功状态；不引入自动批准。

### 7.3 状态和动作不能因视觉清理而消失

[WCAG状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)强调无需移动焦点即可感知状态变化。因此移除正常提示横条时，保留独立role=status区域，并只对重要状态转移播报，不每次2秒轮询重复朗读“已同步”。

历史消息动作可在hover／focus-within时显现，但需预留固定动作区或采用不挤动正文的定位方式；不能鼠标一经过就改变消息高度。触屏、键盘及高对比度模式要有可发现的入口。不能对可聚焦的隐藏按钮添加aria-hidden造成矛盾。

更多菜单使用非破坏性动作的中文标签；菜单、带搜索的历史浮层、非交互Tooltip采用各自语义，不把含输入框的浮层标为menu或Tooltip。关闭时焦点返回触发器，不能自动跳到页面顶部。

### 7.4 工程复用检查

源码核对表明：interactions.js已有Tooltip／确认／详情弹窗，但iconAction是表格范围内的私有、按文案推断图形的增强器；account-menu.js是特定账号菜单的原生details行为。二者不是现成完整聊天组件库。实施时可抽取稳定的图标按钮工厂和通用关闭／焦点行为，显式传icon与中文label，避免继续扩充文案正则猜操作或直接复制账号菜单逻辑。

借鉴PatternFly、Ant Design X和assistant-ui的组织方式，不意味着安装其React运行时。现有原生组件已经能承载所需操作；采用整套框架会扩大依赖与迁移范围，当前没有对应收益证据。

### 7.5 哪些已确认，哪些仍须原型验收

| 项目 | 证据强度／结论 | 后续验收 |
|---|---|---|
| 减少重复工具栏、示例仅空态、技术信息按需 | 有成熟模式支持，结合当前截图问题明确 | 同状态对比截图／DOM，不靠隐藏功能换空间 |
| 所有按钮改图标、标题是唯一历史入口 | 反例风险明确，撤回该默认方案 | 保留新建、历史、发送文字；只对低风险工具图标化 |
| 32px点击区、两行头部、正文65% | 本项目候选参数，不是行业唯一标准 | 不同宽高、缩放／长中文／长草稿下量测；65%不压过操作完整性 |
| 折叠普通回执但保留审批／异常／关键写入结果 | 有规范和执行风险依据 | 在合成审批、部分结果与未知写入场景逐一检查 |
| 自动化通过等于业务人员易用 | 不成立 | 技术回归与人工可用性分开；实施后建议邀请少量代表员工做形成性任务测试 |

建议人工任务：找回上次会话、创建新主题、复制一段结论、拒绝一个权限提案、识别一次缺数、区分收起与停止。记录首次点击、是否需要解释、误操作及主观反馈；当前尚未执行，不编造成功率，也不将小样本当统计结论。
