# 企业办公办公套件：AI安装入口

这是企业管理员生成的完整交付目录。保留整个目录；不要只复制SKILL.md。安装需要互联网下载Python及固定版本依赖，企业服务必须可达。.env是唯一公开连接配置；显式lan-http-demo仅允许私有IPv4明文HTTP开发演示，不用于正式业务。HTTPS仍需正常证书信任。无需预装Python，不修改全局office命令或AI工具配置。

用户把目录放到电脑后，向具备终端和本地文件能力的AI工具发送：

> 请阅读这个目录的INSTALL.md，按其中流程完成企业办公技能套件安装、自检与登录引导，然后确认我的身份和可用能力。本目录为工作目录。遇到密码或浏览器登录步骤由我自行操作；不要向我索取或输出密码、令牌，不修改全局环境和AI工具配置。

## AI执行约定

1. 阅读本文件、公开.env、bundle.json、office-skills/SKILL.md及RULES.md。若.env缺失、地址为空或格式无效，先通过对话询问企业管理员提供的实际服务根地址，由AI生成公开配置；不得猜测localhost、员工电脑IP或自动降级HTTP。通常.env已由管理员从服务端配置派生，员工无需填写；如果需要修改，仅通过对话确认地址与模式并用文件工具写入，不编辑程序或制品清单。仅信任管理员交付的整个目录；摘要是完整性检查，不代替可信来源。
2. Windows执行 `powershell -NoProfile -File ./setup.ps1`。不使用ExecutionPolicy Bypass、不绕过下载标记；公司策略阻止时停止并联系IT。macOS/Linux执行 `bash ./setup.sh`。两个入口均从固定官方发行版下载并核验uv，在目录内使用，不执行远程管道脚本。
3. 脚本校验包、建立目录内`.office/venv`、安装固定依赖和运行doctor。读取`.office/installation.json`，后续只使用其中绝对cli路径与cli_args，**不要调用全局office**。安装失败不得当成完成。安装器还会匿名检查就绪与身份入口，读取connection_verified、connection_issue和next_action；本地installed不代表服务连接成功。若未通过，先询问地址是否正确并检查网络／服务状态，暂不登录或提交数据，不自动换地址。connection_issue给出失败阶段、受控错误码与HTTP状态，不显示服务端响应正文。
4. 首次使用、换地址及连接异常时先运行`"<cli路径>" <cli_args原样参数> connection-check`，不读取凭证；通过只说明入口可达，不证明当前权限。不在每个普通操作前重复探测。随后先运行`"<cli路径>" <cli_args原样参数> whoami`核对身份；未登录或授权失效才运行 `"<cli路径>" <cli_args原样参数> login --timeout 600`（Windows PowerShell在可执行路径前加&），保持进程运行，由用户在同一电脑浏览器登录。如工具不能自动打开浏览器，加`--no-browser`并呈现本次登录链接；不访问身份密码文件、不代填密码。授权链接不是可跨设备使用的登录链接。
5. 用户完成登录后运行whoami、capabilities以及auth-status，确认服务连接和权限。无权限应解释缺少的能力，由管理员处理，不擅自授予权限。不要在验收时创建、确认、修改业务数据。
6. 在当前会话按office-skills入口加载完整规则并使用技能。不能宣称所有AI工具已自动全局注册；宿主专有的技能发现/持久加载须另按宿主支持的方式配置。没有本地终端能力的AI工具不能完成此流程。
7. 凭证仅进入系统安全存储，不写文件明文或聊天；doctor不通过安全后端时停止，不用不安全后端绕过。重复同包同连接安装可修复；地址／模式或包内容变化需使用新目录，不能静默迁移已有凭证。

`.office/installation.json`中的installed仅代表本地安装、自检成功；登录与业务权限检查是单独步骤。不要将整个目录与`.office`复制给其他员工；管理员原始交付包可分别解压使用。


## 用自然语言更换服务地址

用户可说：“将企业办公服务地址改为 https://office.example，检查后连接。”AI先核对目标、用途及公开配置差异，用现有CLI显式--service检查新目标；HTTP必须已有明确授权且显式--lan-http-demo，不能自动从HTTPS降级。连接失败先诊断，不把服务故障当作地址错误直接改写。

检查通过后，由AI用本目录安装脚本生成新的独立连接目录，例如（绝对路径按实际installation.json填入）：

```text
<python> <当前目录>/setup_client.py --uv <当前目录>/.office/tools/uv --stage-connection <新的目录> --service https://office.example
```

脚本只复制已核验的公开制品，不复制.office、令牌、旧安装状态或业务文件，也不覆盖已有目录。AI运行新目录setup、读取新installation.json、再次检查连接，再引导本人登录新服务。原连接和旧服务授权保留，撤销旧授权需另按用户意图操作。不同服务不能复制令牌；同一服务已有合法系统凭证时依正常SDK校验，不要求无故重新登录。员工无需手动编辑JSON或复制目录。

## 不使用AI时

可直接运行setup.sh／setup.ps1。首次未配置或仍为交付占位地址时，脚本在终端询问管理员提供的服务器根地址；HTTP需明确确认。非交互模式不会猜地址，会给出填写.env示例。有效配置不重复询问；已经安装的目录不自动变更身份源。员工电脑不安装服务器／Docker，也不能用自己的网卡IP替代企业服务器地址。
