# 服务端管理工作台

使用服务端Jinja模板与异步应用入口，提供浏览器登录、本人权限说明、人员/角色/权限集管理、授权详情与审计。Web无AI，不调度客户端模型。

- `console.py`处理页面、表单与浏览器授权，调用统一Application；不直接查询/写入数据库。
- `session.py`保存进程内有界会话与待登录状态，Cookie只保存签名引用或短期登录绑定。
- `responses.py`集中处理模板与错误页。
- `templates/`包含布局、共享搜索/分页/权限表、独立样式及各页面。

菜单按当前权限显示，写操作仍由后端校验各操作对应权限、CSRF及所需并发版本；权限管理还检查最后管理员约束。人员姓名、账号安全、全企业授权和审计分别使用独立动作权限，不能一律归为access.manage。隐藏按钮不能代替授权。搜索与跨页编辑保留已选项，并允许明确取消筛选外关联。

当前只适用于单进程会话；多worker/多副本需先增加共享会话适配。登录和身份开户边界见docs/42，控制台配置链路见docs/43。

## 共用交互组件

保留完整页面与原生表单，JavaScript 渐进增强为同页抽屉和短表单弹窗，不另建授权接口。

- `templates/_workspace.html` 是唯一对话框外壳；`base.html` 统一加载。
- `form-state.js` 负责快照、外置选项与授权变更摘要；`workspace.js` 负责加载、预览返回、保存反馈与焦点，不计算真实权限。
- 响应片段只提取服务端 main 内容，不执行响应脚本；相对链接以内容 URL 解析。写入复用原 POST、CSRF 与版本契约；结果未知时不自动重试。
- `styles.css` 集中样式、组件 token 与 reduced-motion；不从 CDN 加载脚本或字体。

设计与来源见 docs/49。新增交互须复用上述入口；修改后检查完整页面、抽屉、无 JS 备用与真实浏览器。新模板和脚本文件须进入 wheel 资源验证。

账号页面在accounts.py，复用console会话、CSRF、render和统一Application。新建用紧凑弹窗、详情用抽屉，预览/进度与敏感步骤保留完整页面；密码响应不经过通用workspace抓取或AI工具。安全回调区分purpose，校验原身份、nonce与近期认证。实现与验收见docs/53。

当前列表默认每页10条，筛选、数字页码、详情与行操作复用统一组件；账号与客户端授权页面按本人／管理范围展示。会话受控续期不延长绝对TTL，近期再认证与退出流程见[72](../../../../docs/ARCHITECTURE.md)及[73](../../../../docs/ARCHITECTURE.md)。页面显隐与前端确认不能替代服务端实时授权。
